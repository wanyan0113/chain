# 从任务与法器生成奥术网

这是独立于原有三个案例的补充展示页。页面使用实际工程的本体推理、属性筛选、候选链评分和资源约束搜索，运行后绘制本次选中链组成的网，不预置最终链或网。

## 启动

在项目目录打开 PowerShell，依次执行：

```powershell
Set-Location -LiteralPath 'C:\Users\Lenovo\Desktop\链'
.\.venv\Scripts\python.exe -B generated/weekly-report-40963d3/demo_server.py --port 8883
```

保留终端窗口。浏览器打开：

- 独立组网页：<http://127.0.0.1:8883/network>
- 原有三个案例：<http://127.0.0.1:8883/>

若8883已被占用，先在旧服务终端按 Ctrl+C，再启动；或者将命令端口改成8884，同时修改浏览器地址。更新服务代码后必须重启服务；只刷新网页不会更新旧服务的接口。已开网页按 Ctrl+F5 刷新。不要直接双击 HTML 文件，页面需要本地计算服务。

## 默认案例

迷雾之海的守护结界附近出现两枚幽光法球，还有一架游移的飞行灵体，三者正在扰动结界。请调配现有法器，同时对它们实施魔法抵消，让结界恢复安宁。

对应下方目标条件：T1、T2为法球，T3为飞行灵体。默认同时开始，距离分别为6、90、30海里，其他目标条件均可在页面编辑。

可用资源是四件灵视探知法器、一个统筹中枢、六枚法球。灵视之眼与统筹中枢可在各自并行容量允许的范围内同时支持多条任务链；每件具现法器仅用于一项任务。页面显示耗时、精度、独立使用成本，并可展开补充属性及十条显式联系。

任务文字是场景说明；程序读取的实际条件是表格中的结构化字段。任务能力需求由外置本体定义推导，数值筛选、联系及协同规则分别检查，没有自动理解任意自然语言任务。

## 主讲操作 五分钟左右

1. 打开独立组网页，先不要运行。读顶部任务，指出三项任务、各自距离和开始时刻。说明“先给目标和资源条件，再让程序选择具体执行方案”。
2. 向下看法器表：灵视之眼、统筹中枢及法球。说明可用状态、并行容量、执行指标都是实际输入。默认不修改。
3. 到“评分与组网”，指出权重为时长0.3、精度0.3、成本0.4，三项之和必须为1。点击“生成并优化奥术网”一次，等待结束。
4. 页面跳到结果。先指网络图：三项任务共享感知魔像灵视之眼和统筹中枢，随后分配不同的法球，形成汇聚与分支。每种线色对应一项任务；左右两端是同一目标的展开画法。
5. 默认输入下，T1、T2、T3分别生成16、8、16条候选链；网中使用法球C、B、E，即R-Sigil-C、B、E。组合评分约0.767229，按次总成本34，总历时8个示例时间单位。这些数值仅适用于默认输入。
6. 指“该任务单独最高分”：T1与T3单独都偏好法球C，但一枚法球不能重复分配。程序为T3选择备选法球E，说明不能把每项任务的独立最优链直接拼成网。
7. 回到法器表，把统筹中枢的“并行容量”从3改为1，其他不动。再运行，出现“当前输入未找到完整可行网”。解释三项任务同时进行，唯一中枢只有一个并行位置，无法支持完整组合。这个演示不会自动重新安排开始时刻。
8. 将中枢容量恢复3，重新运行，确认网恢复。被问到筛选依据时，再展开每项任务的“全部候选与筛选依据”，以及“搜索与协同检查”。

可选补充：关闭法球B的“可用”，重算，观察T2改用其他满足条件的法球，整个组合重新分配。随后恢复默认并重算。不需要把所有JSON逐条讲完。

## 可直接讲的短稿

“这一页承接之前的链生成与组网工作。任务是让三处来袭目标受到魔法抵消，输入包括目标条件、可用法器、执行属性和主体联系。

程序先根据任务推导需要的能力，筛出满足条件的法器，检查联系后形成候选链，再用时长、精度和成本评分。接下来把不同任务的候选放在一起，检查共享容量和法球不能重复分配等约束，选择可行组合。

现在图中共享的灵视之眼和统筹中枢被合并成同一节点，下面分出不同法球，因此最终结果是一张网。图来自本次选中的链，并不是提前画好的最终答案。

这里有一项任务没有采用它单独评分最高的链，因为那枚法球已经被另一项任务占用。程序需要考虑整个组合，不能只把各任务第一名直接拼接。这里的最优，是相对于本次输入、候选集、权重与约束而言。

我再把中枢并行容量从3改成1。重算后找不到完整可行网，说明资源条件确实参与了计算，而不只是改变图上的标签。”

## 计算公式

对每条候选链，环节耗时相加、精度相乘、使用成本相加：

```text
T = Σ t_i
A = ∏ a_i
C = Σ c_i

T' = 1 − (T − Tmin) / (Tmax − Tmin)
A' = (A − Amin) / (Amax − Amin)
C' = 1 − (C − Cmin) / (Cmax − Cmin)
P = wT T' + wA A' + wC C'

网络目标 = 各任务所选链的 P 的均值
```

极值在每项任务本次完整可行候选集内取得。某项指标相同时统一记0.5，避免零分母；仅剩一条候选时亦如此。不同候选集合的归一化评分不应直接用来比较输入条件优劣。网络搜索在每项任务选择一条链的前提下检查资源与协同条件。

精度乘积是当前链评价指标；它与FDNA的SE含义不同，不合并解释。

## 与三个基础案例怎样配合

- 案例一：自然任务叙述 → 生成多环节候选 → 默认展示当前最优链。展开可查看其他候选及链评分公式；权重为原案例的0.4、0.4、0.2，与本独立组网示例不同。
- 案例二：网络图下直接显示图6、表3、表7缩略图，点击放大。基础传播公式位于运行按钮前；结果表仍可逐边检查SoD、CoD与最终SE。
- 案例三：同一网络与原文截图，明确区分六个基础输入节点、五个递推节点及观测SE。指标转SE的公式位于运行按钮前，校准上下界仍是人工示例配置。

本页是链网设计展示，案例二、三是能力依赖计算展示。两种“网”的节点和边含义不同：这里的边表达任务方案中的联系与执行组织，FDNA的边表达能力效能依赖。

运行生成的输入、完整报告和知识文件可在结果最下方打开。文件位于本演示目录的 `runs/运行编号/`，不同运行相互独立。讲完在启动终端按 Ctrl+C 关闭服务。
