入口独立于历史核心程序。导入和RDF查询实际调用 `generated/week2-bbd1f9f` 中的程序；每次运行核对其提交号和核心文件内容，不调用后来增加的成链、评分程序。

## 启动

1. 在 VS Code 打开项目文件夹 `C:\Users\Lenovo\Desktop\链`，选择“终端 → 新建终端”。
2. 在 PowerShell 终端粘贴并执行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\启动Excel演示.ps1
   ```

3. 终端显示地址后，在浏览器地址栏输入：`http://127.0.0.1:8765`。
4. 保持终端运行。结束时回到终端按 `Ctrl+C`。

如果终端当前位于历史目录，先执行：

```powershell
Set-Location -LiteralPath 'C:\Users\Lenovo\Desktop\链'
```

本项目的虚拟环境与历史代码已在当前电脑准备好。入口只监听本机，不需要数据库服务，也不增加第三方Python依赖。换电脑时需要安装 `requirements.txt` 中的依赖，并准备同一历史代码目录。端口被占用时可改用：

```powershell
.\.venv\Scripts\python.exe -B -m excel_entry.app --port 8766
```

然后打开 `http://127.0.0.1:8766`。

## 现场展示建议

先演示上面的原始导入，再做一次能看到变化的操作：

1. 将示例另存为自己的演示副本。
2. 打开“作用能力”工作表，把第2行 `R-Sigil-A` 的“最大作用距离（n mile）”从10改成12。保存并关闭。
3. 回网页重新选择这个副本并点“导入”。
4. 再查询 `R-Sigil-A`，最大作用距离会变成12。展开“查看运行依据”，可查看输入摘要和结果目录。
5. 回表格将这个数字删除，保存，再导入：应提示“作用能力第2行”缺少数字。失败时不显示上一轮的成功结果。
6. 恢复该数字，重新导入即可。

结果目录位于 `generated\excel-runs\每次运行目录`，包含：

| case_records.json | 自动转换后交给历史程序的输入 |
| ingest.log、query.log | 历史程序本次实际运行的输出 |

## 填写新数据

新案例使用“空白模板”。表名和第一行列名固定；记录行可以增删、排序，四张数据表都至少一行，“任务”只支持一条。

| 工作表 | 填什么 |
| --- | --- |
| 对象清单 | 所属方、名称、唯一编号、数量 |
| 探测能力 | 平台、坐标原列值、高度、资源、目标类型、探测距离、精度 |
| 作用能力 | 平台与资源、适用目标、距离、高度、速度、作用值及概率 |
| 任务 | 目标类型、位置、高度、速度和阈值 |
| 案例说明 | 核对日期、资料来源、单位、名称对应和缺失事实 |
| 事实 | 从正文整理的主体、关系、客体和来源；没有可留空 |
| 疑点 | 人工核对发现的问题、说明、来源和关联字段；没有可留空 |
| 填写指南 | 简短填写规则 |

数值直接填数字，不能加单位或公式。概率填95表示95%，不是0.95。多个目标类型用分号分隔。0保留为0，必需数值空白会报错。高度使用ft，距离使用n mile，速度使用kn，当前不自动换算。

“案例说明”的来源行必须填写真实资料的文件名称或路径，至少包括对象清单、能力表、任务、正文资料。核对日期用文本 `YYYY-MM-DD`，如 `2026-10-27`；在Excel中可先输入英文单引号以保持文本。其余单位说明保留，必要时核对未确认单位的文字。没有“规则表资料”等可选来源行时可删除整行。

疑点的关联字段使用 `工作表名::唯一编号::列名`，例如：

```text
作用能力::R-Sigil-D::最小作用距离（n mile）
作用能力::R-Sigil-D::最大作用距离（n mile）
```

整表问题只填工作表名，例如 `作用能力`；正文缺失问题可以关联 `事实`、`缺失事实`。多个字段或来源文件各占一行，Excel可用 `Alt+Enter` 换行。关联按编号解析，排序不会让疑点串到别的对象；修改编号或删除对象后需更新关联，否则报错。

程序自动做格式、数字类型、必填、编号重复、部分边界以及来源和字段引用检查；历史程序继续做来源包结构、一致性与RDF查询。已有业务疑点仍是人工登记内容，修改数据后要人工复核疑点说明。`valid`不表示业务规则全部成立。
