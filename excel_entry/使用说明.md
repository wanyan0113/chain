## 综合Excel：从原参数到设计

### 开启表10原文条件

先在“链网设计”下载“表10校验综合示例（虚构数据）”，它同时支持来源查询，并已在设计设置登记“表10原文校验”，值为文本true。上传后可查看自动生成的候选链、网络以及“表10原文条件核验”和“网络组合核验”。模板中的参数均为工程构造值，不是文章真实实例。

自己的完整设计文件也可在“设计设置”新增同名行并填true；填false或不登记该行则沿用原有工程模式。该开关会执行内置原文条件，不替代自己的任务→能力规则和法器能力规则，也不自动补齐所需事实。不同约束同时生效。

属性字段采用下列名称，单位必须明确且比较双方一致：

| 对象 | 字段 |
| --- | --- |
| 任务 | target_type、impedance、target_speed、target_altitude、target_count |
| 探知法器 | target_types、detection_range、max_tracks |
| 协调法器 | max_processing_targets |
| 具现法器 | target_types、min_range、max_range、resonance、max_target_speed、min_target_altitude、max_target_altitude、min_activation_altitude、max_activation_altitude |
| 任务—法器情境 | target_distance；具现情境另填platform_altitude |

target_count、max_tracks、max_processing_targets填写正整数数值，单位1；未知可以留空，不当作0或无限容量。其他参数可通过“来源取值”从原表引用，声明单位和相关疑点会保留。需新增的任务数量、标记数和解析数必须另有依据，不能根据想得到的结果倒填。

开启后，“大于/小于”按严格边界执行。共享资源数量比较使用目标数量总和，不是链条数；最大值等于总数不通过。组网逐个核验实际同时执行的任务组合（整链区间），首尾相接不算并行。具现法器全计划不得重复，串行时也不因库存充足而自动允许重复。该规则比原工程资源约束更严格，页面会分别展示两者的冲突。

未知且仍可能可行的组合会阻塞最优结论，即使已经找到另一个已知可行组合，也不会直接选它。原文条件明确失败则排除相应法器或组合。只有完整通过且规范能力映射、RDF静态检查也通过时才导出RDF；表10证据保存在design_report.json，并可在网页展开。

本次接入的是静态设计与核验；原文坐标、范围、精度身份和缺失资源数据问题仍保留，文章案例页也不会自动变成已验证的真实网络。

下载“综合设计演示（虚构）”先试跑。该文件的来源数据和设计配置全部为虚构工程配置，不混用文章原始参数。先在“Excel 来源与参数”上传查询，再到“链网设计”上传同一文件，可看到双任务候选链、共享资源约束下选出的网络，以及“原参数取值与来源”表。

“文章来源示例”仍保留原值和疑点，新增设计表为空，不声称文章案例已经能自动生成链网。“综合空白模板”用于自行整理资料。以前下载的旧文件仍可查询；要生成链网，需将自己的原始数据复制到新版模板，并补齐设计表。仅增加工作表不会自动补出缺失的业务配置。

| 工作表 | 填写内容 |
| --- | --- |
| 最初八张来源表 | 参数、原始任务、单位、正文事实、来源与登记疑点，原结构保留 |
| 设计设置、设计任务 | 范围、权重和明确的计算政策；实际目标编号和开始时间，可配置多任务 |
| 法器 | 角色、可用性、三阶段指标和成本口径、容量、库存、冷却及来源 |
| 属性、来源取值、情境 | 新属性或按唯一编号引用原字段，以及任务与法器之间的距离等事实 |
| 规则、规则条件 | 明确的任务需求和法器筛选条件、能力名称、阈值、单位和来源 |
| 协同关系 | 有向传讯与统筹边、距离与最大距离、来源和疑点 |
| 任务依赖、资源组 | 可选前后顺序与共享资源限制，无此约束时留空 |
| 设计指南 | 各表填写说明，绿色页签属于设计配置 |

在“来源取值”填设计对象类型、对象编号、属性字段和来源工作表、来源编号、完整列名。例如：对象类型“法器”、对象编号“demo-fast”、属性字段“max_range”、来源工作表“作用能力”、来源编号“demo-fast”、来源字段“最大作用距离（n mile）”。情境类型另填情境法器编号。探测能力表的来源编号是平台编号，任务表的来源编号是任务名称。引用按编号查找，调整数据行顺序不改变引用。

同一属性选择“属性”手填或“来源取值”引用其一，重复会报错。每次上传重新读取当前源值，保留声明单位，不将百分数自动当作0至1精度，也不把作用值当成本。被引用字段的登记疑点、自动发现的边界矛盾和未知单位会带入对应设计对象，阻止把未确认事实当作通过。未引用的来源参数不会自动成为筛选条件，实际物理约束仍需明确写入规则。

设计结果额外保存 `source_bindings.json`，包含来源快照、逐项取值及疑点；核心 `design_input.json` 和规则证据包含实际消费的属性及来源。来源查询页不执行设计，设计页不执行来源实例的HermiT检查；设计RDF仍使用原有严格静态检查。

模板重建：先保留原专用设计模板，然后将 `excel_entry/build_unified_templates.mjs` 复制到项目 `tmp` 下，通过指向技能运行时 `node_modules` 的junction运行。脚本读取 `excel_entry.template_spec` 契约，保留原来源模板数据，追加或刷新设计表；副本、检查与预览保存在 `tmp/unified-templates`。重建会覆盖模板中的设计配置，自己的工作簿请另存。

完整链网设计使用独立页面 `http://127.0.0.1:8765/design`，也可从首页点击“完整链网设计”。

如需试跑文章第三部分截图，点击页面里的“试跑文章第三部分案例”，进入 `/article-case`。该页复算表13，展示正文给出的最优链及两链结构，并提供SVG和JSON下载。它标注未独立验收的部分，不替代完整设计Excel的筛选、资源约束或仿真。

1. 下载“双任务示例”，先直接上传运行一次。示例为虚构工程配置，不能作为文章案例依据。
2. 查看每个任务的两条候选链，以及网络选中的一快一慢两条链。两个任务共享探知和协调法器；同时使用快速具现法器会违反容量和库存约束。
3. 在“法器”表将 `demo-fast` 的容量和库存都从1改为2，保存并重新上传。两个任务此时都能选快链，网络平均评分从0.5变为1。
4. 换成真实数据时使用空白模板，按“填写指南”提供任务、规则、属性、情境、协同边、指标和资源约束。空白设置必须明确填写，程序不会代填权重或阈值。
5. 缺少事实或指标时会显示阻塞原因；结构错误直接报错。每次运行保存到独立目录，避免旧成功方案与新失败结果混淆。

结果目录包含 `input.xlsx`、`design_input.json`、`design_report.json`、`design_summary.md` 和 `run_result.json`。仅设计完整、规范能力映射齐全且本体静态检查通过时生成 `design.ttl`。完整规则判断和来源可展开查看。此入口不执行HermiT，启动脚本的 `--reasoner` 仅影响旧案例导入。

“链网结构”区域从左向右读：目标 → 探知法器 → 协调法器 → 具现法器 → 原目标。目标蓝色、探知绿色、协调橙色、具现红色。两端同名目标为同一对象的两次展示，不是两个新目标。图不表示物理位置或时间轴；任务编号、评分及选中情况在图下“图与任务的对应”表中展示。

通过“查看范围”切换“选中网络”“全部候选链（逐行）”或单条链。全部候选链每行五个圆点，用①②等序号对应图下表格；选中网络将共同使用的法器合并为一个圆点，重复协同边只画一次。主图中的每条箭头来自报告里实际存在的链；任务间串行、并行、分支和共享关系在图外折叠区查看。

未被选中的单链会标注“候选链预览”，阻塞或无解时不生成选中网络图。点击节点或按Tab聚焦后按Enter，可查看参与的链、对应规则、条件判断、来源及协同证据。“下载当前图 SVG”保存当前视图：网络为 `selected-network.svg`，全部候选为 `candidate-chains.svg`，单链用其编号命名，便于区分。新上传失败后，旧结果会隐藏。

无需网页也能运行：`.\.venv\Scripts\python.exe -B -m excel_entry.app --design-file '.\excel_entry\templates\链网设计示例.xlsx'`。

`--design-file` 的退出码：0表示设计完整且RDF已通过静态检查并导出；1表示设计阻塞、无可行方案或规范能力映射未就绪；2表示输入／读写错误、搜索上限或RDF静态检查失败。PowerShell可通过 `$LASTEXITCODE` 判断。RDF静态检查失败时仍保留报告，网页显示方式不变。

通用规则验证使用独立模板和页面：打开 `http://127.0.0.1:8765/rules`，或点击首页的规则验证链接。步骤及示例说明见 [任务规则验证](../rule_review/使用说明.md)。

导入和RDF查询直接调用当前项目的 `source_data` 模块，不再依赖历史代码目录。网页执行数据导入、校验、查询及描述性本体实例映射。

每次成功导入后，结果目录的 `results` 下还会生成 `cleaned_case.json` 和 `cleaning_report.json`，分别保存文本与列表清洗后的派生数据、变更及单位换算明细。来源包仍保留原始输入。清洗也能脱离网页和实例映射独立执行，参见 [数据清洗说明](../source_data/数据清洗说明.md)。

## 填写新数据

导入后，“关联本体实例”显示当前记录对应的类型、承载关系和来源记录。当前只映射明确的描述属性，未确认字段保留在来源层，不自动解决疑点。具体范围见 [案例实例映射说明](../adapters/案例实例映射说明.md)。

新案例使用“空白模板”。表名和第一行列名固定；记录行可以增删、排序，四张数据表都至少一行，“任务”只支持一条。

| 工作表 | 填什么 |
| --- | --- |
| 对象清单 | 所属方、名称、唯一编号、数量 |
| 探测能力 | 平台、坐标原列值、高度、资源、目标类型、探测距离、精度 |
| 作用能力 | 平台与资源、适用目标、距离、高度、速度、作用值及概率 |
| 任务 | 目标类型、位置、高度、速度和阈值 |
| 案例说明 | 核对日期、资料来源、单位、名称对应和缺失事实 |
| 事实 | 从正文整理的主体、关系、客体和来源；没有可留空 |
| 疑点 | 人工核对发现的问题、说明、来源和关联字段；没有可留空 |
| 填写指南 | 简短填写规则 |

数值直接填数字，不能加单位或公式。按默认模板单位，概率填95表示95%。多个目标类型用分号分隔。0保留为0，必需数值空白会报错。默认高度为ft、距离为n mile、速度为kn；其他已支持单位必须在“案例说明”的单位行明确声明，同类字段全部使用该声明单位。固定列名仍用于定位字段，实际输入单位以声明为准，网页显示原始值时使用声明单位；本体实例使用转换后的标准单位。概率单位若声明为 `1`，则填写0至1。具体支持范围见实例映射说明。

“案例说明”的来源行必须填写真实资料的文件名称或路径，至少包括对象清单、能力表、任务、正文资料。核对日期用文本 `YYYY-MM-DD`，如 `2026-10-27`；在Excel中可先输入英文单引号以保持文本。其余单位说明保留，必要时核对未确认单位的文字。没有“规则表资料”等可选来源行时可删除整行。

疑点的关联字段使用 `工作表名::唯一编号::列名`，例如：

```text
作用能力::R-Sigil-D::最小作用距离（n mile）
作用能力::R-Sigil-D::最大作用距离（n mile）
```

整表问题只填工作表名，例如 `作用能力`；正文缺失问题可以关联 `事实`、`缺失事实`。多个字段或来源文件各占一行，Excel可用 `Alt+Enter` 换行。关联按编号解析，排序不会让疑点串到别的对象；修改编号或删除对象后需更新关联，否则报错。

程序自动做格式、数字类型、必填、编号重复、部分边界以及来源和字段引用检查；数据处理模块继续做来源包结构、一致性与RDF查询。已有业务疑点仍是人工登记内容，修改数据后要人工复核疑点说明。`valid`不表示业务规则全部成立。
