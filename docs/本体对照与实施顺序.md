## 二、本轮的建模决定

### 1. OODA 四阶段与三类角色同时保留

| 阶段 | 任务类 | 能力类 | 装备类 |
| --- | --- | --- | --- |
| O1 探知 | ReconMission | ReconCapability | ReconEquipment |
| O2 研判 | JudgmentMission | JudgmentCapability | JudgmentEquipment |
| D 决断 | DecisionMission | DecisionCapability | DecisionEquipment |
| A 施法 | StrikeMission | StrikeCapability | StrikeEquipment |

中间两行分别属于指挥任务、指挥能力、指挥装备的父类层级。因此“三类角色”和“四阶段”不是矛盾，不必删除指挥父类，也不必让指挥父类只对应某一个阶段。

阶段通过 `correspondsToPhase` 注解标注。这是对类的说明，不是实例执行关系，也不是能由推理器自动传播的对象属性。`Judgment*` 增加“研判”别名，原来的“占卜”显示名及英文 IRI 保留。

表 4 的“解析能力”保留为 `EvaluationCapability`。资料没有明确说明它与 `JudgmentCapability` 等价，所以不擅自添加 `owl:equivalentClass` 或新继承关系。

### 2. 类定义不强制每个实例具有后续任务

0.6 中 `CommandControlMission` 要求存在后续 `StrikeMission`，其研判、决断子类也继承该限制；侦测任务还要求存在后续指挥/研判任务。这并非仅仅说明 OODA 的典型顺序，而是要求每一个该类实例都存在相应后继。

0.7 删除这五条时序存在性限制，保留任务所需能力的原有存在性限制。具体任务的先后关系仍可通过实例上的 `finishStartPrecedes` / `startsAfterCompletionOf` 显式表达。此变更会减少原本可从任务类型推出的后继存在性结论。

OODA 是阶段上的循环，不意味着一次执行中的 `nextNode` 必须回连首节点；后者会制造依赖环。下一轮观察应作为新的任务发生记录，而不是强制把一次依赖链连成环。

### 3. 角色、载体和参与节点是不同维度

- 同一实体可兼具侦测、指挥等角色，因此不新增角色类之间的互斥公理。
- `EquipmentPlatform` 描述承载平台，功能角色类描述职责；两者可多重继承。
- `mountedOn` 表示可分离物理挂载；`hosts` 表示常驻/集成节点，不能简单互换。
- 同一资源出现在不同链时，分别建立参与节点，再指向同一个资源实体；共享资源不等于共享带有单一序号的参与节点。

### 4. 单位、指标和显示名分开

本轮增加 `unitSymbol` 注解，覆盖主要的距离、高度、速度、时间、角度、带宽、功率和无量纲指标。它不强制范围、不执行换算。现有海里、英尺、节等单位保持原口径。

`missionTime` 是 `xsd:dateTime` 时间点，不能直接当作任务耗时。`reconIntervalS` 是侦测间隔，`responseTimeS` 是响应时间，都不能未经定义就直接当成表 6 的阶段总耗时。

距离/角度误差、0—1 汇总精度、命中概率是不同指标；截图未给出转换公式。`cost` 使用成本的币种和计价基准也须由实例数据说明。魔法化中文显示名不自动改变英文取值，例如 `ship` 仍是原字符串。

## 三、第二部分规则应怎样理解

| 条目 | 记录内容 | 尚未包含 |
| --- | --- | --- |
| TaskCapabilityRuleDescription | 任务条件与所需能力的关系 | 可执行条件、阈值或推理规则 |
| CapabilityEquipmentRuleDescription | 能力需求与资源属性的映射 | 候选资源筛选与正式分配 |
| EquipmentCooperationRuleDescription | 协同条件的合取含义 | 全局连通性、时序或冲突判定 |
| ChainCooperationRuleDescription | 串联、并列、分支和共享的来源说明 | 可执行的链网生成与优化 |

式（1）—（3）的交集符号表达“条件同时满足”，本体文本目录用 AND 记录。截图省略了变量量化、阈值、规则作用域和某些全局条件；不能把它们直接当成完整的一阶逻辑或可运行的 SWRL。

OWL 的 domain/range 用于类型推理，不等于数据表的录入限制。`someValuesFrom` 也不要求输入文件中必须显式列出某个具名实例。必填、数值边界、同链归属和序号连续性属于 SHACL 或程序数据校验层。

## 四、公式记录和适用口径

式号与截图一致；以下只做来源整理，不增加来源没有提供的性能模型。

| 式号 | 表达式 | 口径 |
| --- | --- | --- |
| 1 | `(t_i^1 ∧ … ∧ t_i^n) → c_i` | 任务属性条件同时满足 |
| 2 | `(c_i^1 ∧ … ∧ c_i^n) → w_i` | 能力相关条件同时满足 |
| 3 | `(w_ij^1 ∧ … ∧ w_ij^n) → l_k` | 协同条件示意，不是完整构链算法 |
| 4 | `T = T_o + T_d + T_a` | 阶段耗时单位一致且不重叠；截图暂不考虑传讯类法器 |
| 5 | `A = A_o A_d A_a` | 需先明确阶段精度的定义和乘积合成的适用性 |
| 6 | `C = C_o + C_d + C_a` | 使用成本口径、币种一致 |
| 7 | `T′ = 1 − (T − min T)/(max T − min T)` | 时间越小，归一化结果越大 |
| 8 | `A′ = (A − min A)/(max A − min A)` | 精度越大，归一化结果越大 |
| 9 | `C′ = 1 − (C − min C)/(max C − min C)` | 成本越小，归一化结果越大 |
| 10 | `P = w₁T′ + w₂A′ + w₃C′` | 各权重在 [0,1]，和为 1 |

式（7）—（9）的 min/max 必须来自同一明确比较集合。当某指标 `max=min`，包括仅有一个方案时，截图中的公式分母为零；资料未规定该情形，应另行约定，不能无说明地填入一个分数。更换比较集合也可能改变归一化值。

表 6 的 `T_o/T_d/T_a`、`A_o/A_d/A_a` 并未在截图中给出完整的底层字段计算方法。当前本体不把响应时间、侦测间隔或命中率直接重命名成这些分项，也不把单链的加法直接推广为共享资源网络的总成本。

## 五、实施顺序和交付界限

1. **核对并完善本体，当前轮完成。** 覆盖第一部分核心类、角色层级和字段，补来源、阶段、单位和建模说明，消除任务类与实例流程的混淆。
2. **完善数据校验，基础工具已完成。** 新增 `validate_data.py`，在独立 JSON 配置层检查必填项、类型、数值范围和依赖环；以维修示例和 14 项正反例测试验证。单位目前只有语义约定，不自动换算。使用方式与边界见 [数据校验使用说明](数据校验使用说明.md)。
3. **建立通用示例并验证语义。** 可沿用已有设备维修或仓库示例，验证任务—能力—资源之间的关系。区分需求、候选、正式分配与执行记录。该阶段不把文献中的攻击装备选择或攻击链生成做成可执行功能。
4. **整理规则层，与本体分离。** 已完成规则目录和 2.1.1 的维修两级映射验证。2026-10-24 新增 2.1.2/2.1.3 的维修协同验证：有序流程、授权/格式交接、固定窗口容量、耗材及流程组合；新增 26 项测试通过，连同前序共 52 项。详见 [映射规则验证](第二部分2.1.1映射规则验证.md)及[流程协同验证](第二部分2.1.2与2.1.3流程协同验证.md)。这是独立非武器示例，未实现主本体的领域规则或最优排程。
5. **整理指标并做通用数据验证。** 本轮已经完成十个公式的文本目录和口径说明；后续先确定指标定义、计价方式、比较集合、缺失值及零分母政策，再在非武器流程示例中验证。
6. **最后做展示、导入和版本归档。** 校验结果稳定后再导入图数据库或制作可视化；保留来源说明和复现命令。图中有边不代表业务条件已经满足。

本轮没有实现目标拦截、攻击装备筛选、攻击链生成或攻击方案评分优化程序。对规则和公式的记录不代表具备这些执行能力。

## 六、验证方式

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe check_ontology.py killweb_ontology.ttl --fail-on-warn --json-output tmp/ontology-v0.7-check.json
```

这覆盖 Turtle 解析、现有静态模式及项目检查。没有具体链实例时，链结构检查的零条链不能证明实例场景正确。完整 OWL 一致性仍需在 Protégé 中使用 HermiT 等推理器另行确认。本轮不声称执行过完整 OWL 推理。

2026-10-23 本轮实际执行结果：静态检查通过，ERROR=0、WARN=0；共 1058 个三元组，48 个类、38 个对象属性、80 个数据属性、44 个命名个体。另核对原有对象/数据属性集合保持一致、五条类级时序限制已移除、12 条阶段注解均存在、单位注解均指向已声明的数据属性、4 条规则说明与 10 条公式记录齐全。`git diff --check` 通过。
