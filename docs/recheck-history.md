# 本地复核历史与固定报告链接

“优化成果”新增“本地网页复核记录”。服务重启后，仍能查看已配置来源中的最近20条任务记录，打开图文报告或下载JSON；启动下一次任务不会改变上一次报告的链接。它与当前服务会话的任务、最近发布的完整复核快照分别显示。

启动方式仍为[网页完整复核说明](web-recheck.md)中的`--review-project-root`。记录保存在该项目根目录下的`generated/关于优化/15_网页完整复核/运行记录/`。历史接口只读，不启动子进程、不恢复旧任务、不改写状态文件。

| 入口 | 行为 |
| --- | --- |
| `GET /fdna-results/recheck/history` | 最近20条本地记录，含状态、报告可用性和固定链接 |
| `GET /fdna-results/recheck/jobs/<任务编号>/report` | 指定任务的图文报告 |
| `GET /fdna-results/recheck/jobs/<任务编号>/report.json` | 指定任务的JSON报告 |
| 原无编号报告地址 | 继续指向当前服务会话的最近已完成任务；新会话未运行时无报告 |

任务编号严格限制为32位小写十六进制。读取时检查目录范围、状态编号、完整报告结构和三个产物的精确字节摘要。状态或报告不一致的原通过记录显示“记录检查未通过”；单条损坏不会遮住其他正常记录。失败任务若有完整诊断报告仍可阅读，但保留失败状态。

当前会话运行中的任务不提前提供报告。其他会话遗留的running记录标为“运行状态未确认”，不推断它已经中断或完成；即使已有可校验报告，也单独保留报告状态，不自动升级任务状态。

本轮还修复了Windows并发读写状态文件时的替换拒绝：同一管理器使用同一把锁同步状态读取与保存，对短暂文件占用最多尝试三次；持续失败仍返回失败，不无限等待或留下虚假的运行中状态。
