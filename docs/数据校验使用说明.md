# 数据校验使用说明

`check_ontology.py` 检查本体静态结构；新增 `validate_data.py` 根据独立的 JSON 配置检查显式实例数据。二者作用不同：前者通过，不代表实例没有漏填；后者通过，也不代表完整 OWL 逻辑一致性得到证明。

## 运行

复用项目已有的 rdflib 环境，无新增第三方依赖。在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe validate_data.py maintenance_demo/maintenance_ontology.ttl --profile examples/maintenance_data_profile.json --json-output tmp/maintenance-data-check.json
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_data_validation.py -v
```

本轮实际结果：检查维修示例的 11 个实例，0 个错误；14 项测试全部通过。本体 0.7 的静态检查同时通过，0 个错误、0 个警告。JSON 报告保存在 `tmp/maintenance-data-check.json`。

若模式和实例分开存储，可用一个或多个 `--schema local-schema.ttl` 加载本地模式。程序不自动下载或展开 `owl:imports`。加载文件的三元组合并后进行检查，因此模式文件里自带的实例也会进入检查范围。

## 已实现的检查

| 配置项 | 检查 |
| --- | --- |
| target_class | 检查该类及其具名子类的显式实例；配置中的类必须已声明 |
| require_instances | 默认 true；没有目标实例即报告 NO_TARGET，防止检查范围意外为空 |
| min_count / max_count | 属性值数量下限/上限，按 RDF 图中不同的对象计数 |
| datatype | 字面量类型与词法有效性；支持整数类型向 decimal 的派生兼容 |
| value_class | 关系对象须有要求的显式类或具名子类类型 |
| min_value / max_value | 数值边界，包含边界值；拒绝 NaN、无穷大等非有限数值 |
| acyclic_properties | 所列依赖属性的显式边不能有自环或环路 |

配置使用完整 IRI，避免命名空间前缀歧义。未知配置项、拼写错误、反向边界、未声明属性等会被报告。输出报告不能覆盖输入数据、模式或配置文件。

维修配置要求任务具有能力和非负的单值耗时，资源具有服务能力和单值布尔可用标记，维修要求具有非负期限，依赖关系无环。`available false` 是有效数据，校验不把“不可用”等同于“填错”。数值和单位使用现有维修示例的分钟口径。

## 检查边界

这是小型 JSON 配置校验器，不是 SHACL 实现，也不自动根据 OWL 的 domain/range 或存在限制补齐事实。复杂类表达式、等价类、sameAs、跨字段数值比较和单位换算尚未实现；未配置的字段不作必填或范围检查。

依赖无环检查只检查配置中指定属性的显式图，不自动展开逆属性或子属性。它不验证资源分配、排程、任务期限是否满足或规划方案是否可行。

当前校验配置用于独立的维修示例；没有把武器或攻击链的业务条件转换为可执行校验规则。不要把维修示例通过表述为所有本体实例均已验证。

退出码：0 为校验通过，1 为发现实例/配置声明错误，2 为输入读取、解析、配置格式或报告写入错误。JSON 实例校验报告包含输入路径、配置路径、模式路径、错误代码和统计。输入读取或配置格式错误时，当前仅输出终端说明，不生成 JSON 报告。
