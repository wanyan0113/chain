## 规则一：任务条件推导所需能力

输入任务只填写任务种类、设备种类、是否需要留档和响应上限；不预填 `requiresCapability`。

| 规则 | 同时满足的条件 | 推导能力 |
| --- | --- | --- |
| InspectPumpRule | 设备为 pump，任务为 inspect | detect 检测能力 |
| RecordPumpRule | 设备为 pump，任务为 inspect，需要留档 | record 记录能力 |
| RepairPumpRule | 设备为 pump，任务为 repair | repair 维修能力 |

同一任务可以命中多条规则。例如“检测泵站并留档”得到 detect 和 record 两项需求。通过 `matchedTaskRule` 记录命中的规则，报告保留原始任务条件，便于追溯。

这些规则是为教学案例明确设定的政策，不是从任务类型的中文标签猜测能力，也不是已经实现自然语言理解。未知任务或设备种类不会自动匹配近义词。

## 规则二：所需能力推导候选资源

`resource_rules.rq` 要求下列条件同时成立：

1. 任务至少有一项推导出的能力需求。
2. 单个资源提供全部所需能力，按能力 IRI 精确匹配。
3. 资源有显式的 `available true`。
4. 资源响应时间不大于任务的响应上限，单位均为分钟。

响应时间等于上限时允许成为候选。多个资源分别提供部分能力，不会自动拼成一个联合候选；资源团队组合属于后续另外定义的问题。

输入校验先检查每个字段的数量、类型和数值范围，避免多个 available 值、负数或错误类型参与规则推理。规则只沿具名 `rdfs:subClassOf` 路径识别任务和资源，不执行完整 OWL 推理。

## 实际结果

| 任务 | 推导需求 | 候选资源 | 说明 |
| --- | --- | --- | --- |
| 快速检测泵站 | 检测 | 基础检测仪 | 响应 0.5 分钟，不超过 1 分钟 |
| 检测泵站并留档 | 检测、记录 | 带记录功能的检测仪 | 同时具备两项能力，响应 2 分钟，不超过 5 分钟 |
| 维修泵站 | 维修 | 维修服务组 | 响应 3 分钟，不超过 5 分钟 |

基础检测仪无法满足留档任务，原因是缺少记录能力。停用检测仪即使能力齐全也被排除；响应较慢的检测仪因超时被排除。这些原因都写入报告，不仅显示“没有匹配”。

报告有三种任务状态：

- `matched`：推导出能力并找到至少一个候选。
- `no_matching_task_rule`：任务条件未命中任何能力规则；不会把空需求解释成所有资源都满足。
- `no_candidate_resource`：已有能力需求，但没有单个资源同时满足全部条件。

## 运行和文件

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m maintenance_demo.mapping.run_mapping
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_mapping.py -v
```

运行器也支持 `--input 本地文件.ttl` 和 `--output-dir 输出目录`。输入会和本目录的 `schema.ttl` 合并；不要加载旧示例实例或已有推理输出，否则会混入另一批任务。原始输入中若包含能力需求、候选关系或命中规则记录，程序会拒绝运行，以免旧结论污染重新计算。

| 文件 | 用途 |
| --- | --- |
| schema.ttl | 本演示使用的独立模式和能力、规则词项 |
| input.ttl | 3 项任务、5 个资源的原始条件与事实 |
| input_profile.json | 推理前的数据质量要求 |
| task_rules.rq | 第一级 SPARQL CONSTRUCT |
| resource_rules.rq | 第二级 SPARQL CONSTRUCT |
| run_mapping.py | 校验、顺序执行、解释和导出 |
| generated/inferred_capabilities.ttl | 第一级产生的能力需求和命中规则 |
| generated/candidate_resources.ttl | 第二级产生的候选关系 |
| generated/merged.ttl | 模式、输入和本次推理结果合并图 |
| generated/mapping_report.json | 条件、能力、候选、排除原因、规则文本 SHA-256 和结果统计 |

退出码：0 为所有任务都有候选；1 为规则运行完成但有任务未匹配，仍导出诊断；2 为输入、校验或文件读写失败。运行失败时不会清理上次的输出，应先查看本次退出码，避免把旧文件当作新结果。

SPARQL 规则由 Python 显式执行；在 Protégé 中打开 TTL 不会自动执行这些查询。可打开 `generated/merged.ttl` 查看已经生成的关系。
