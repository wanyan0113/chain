# 第一阶段需求分析与现状差距

## 目标与边界

输入结构化任务需求和活动知识，根据前置条件与确定性效果生成有界顺序活动实例序列，独立重放验证后交给后续分析。流程长短取决于目标、初始状态与活动规则，不要求预先枚举完整模板。验证是对声明模型的验证，不证明现实执行效果。

首版支持有限对象域、有限参数域、显式否定与未知、活动重复上限、必须发生的活动、空流程、派生事实失效重算、候选恢复搜索及有限范围反馈。数值状态的有限精度、单位与合法运算在第二阶段冻结；不允许任意连续参数取值。

并行、条件分支、概率效果、实时重规划、自然语言理解、具体装备协同优化均不在首版范围。采用任务书要求的通用文档业务例子，不添加具体部署或武器运用规则。

## 现有模块及证据

下列结论依据基线源代码，而非仅根据提交说明判断。

| 源文件 / 函数 | 已有能力 | 对新需求的限制与处理 |
| --- | --- | --- |
| `design/engine.py:infer_task_capabilities`、`design/capabilities.py:infer_capabilities` | 外置规则及OWL能力需求；独立能力推理入口 | 角色与输入契约受原模型约束；保留原逻辑，经映射适配复用 |
| `design/knowledge.py:knowledge_context` | 本地知识文件、来源快照与摘要、OWL及规则上下文 | 没有活动前置条件/效果驱动的搜索；不能把规划状态混入永久本体 |
| `design/owl_scene.py:reason_scene` | HermiT场景推理及具名结论回流 | 非任意动态状态执行器；新增状态需独立映射及重算政策 |
| `design/sequences.py:validate_sequences` | 外置顺序模板校验 | 至少三步、observe开头、含decide、act结尾或act后显式assess；仅四种活动，不接收任意通用流程 |
| `design/sequences.py:generate_task` | 逐环节能力/类型/等级筛选、连接剪枝与对象选择 | 环节序列仍由模板给定；不从目标条件推理活动数量；每步一个执行对象 |
| `design/engine.py:_design`、`design/schema.json` | 链、评分、网络选择 | 完整入口要求原资源/评价字段；不能用虚构指标填空接通通用逻辑规划 |
| `design/plans.py:resource_conflicts`、`design/search.py:branch_and_bound` | 容量、库存、冷却、资源组和任务先后约束 | 固定时间安排，不自动排程；不能用最终状态去重替代资源判断 |
| `fdna/equipment_bridge.py:bridge` | 已选链、直接产品消费、主体与任务产品身份登记 | 显式限制 `single_unit_per_role`；不支持任意 `ordered_steps` 或通用流程自动导出FDNA |
| `fdna/flow_scenario.py:independent_enumeration`、`check_design` | 三任务合成场景的独立链网枚举对照 | 不是活动状态规划的独立穷举器，不能代替新规划实验 |

## 当前差距与工作拆分

1. 第二阶段：正式活动/状态契约、类型检查、事实身份、规则子集、来源及版本策略；布尔例子先行，数值运算单独验收。
2. 第三阶段：确定性有界搜索，支持首解/恢复与完整枚举；状态相同的不同活动序列仍保留其身份。
3. 第四阶段：独立语义实现重放器，逐步轨迹、错误定位和变异流程拒绝实验。
4. 第五阶段：活动能力输出、旧入口适配及反馈管理；通用流程不强制压成三角色链。
5. 第六阶段：模板对照、穷举、边界、语义异常、错误流程和端到端实验。

## 外部样本的定位

本地 `formation_generator` 提供目标、资源、能力和连接关系，不能替代活动前置条件、效果和任务完成条件知识。它目前未纳入本研究提交，不能作为普通克隆的隐含依赖。首版以本目录的通用业务示例表达需求；已有桥接实验仅作为回归基线。任何后续外部数据接入均须登记格式、映射及适用范围。
