# 阶段验收与实验计划

## 第一阶段完成条件

- 已记录实际开发基线和任务书摘要。
- 已按函数与接口盘点推理、顺序模板、组网及FDNA桥接的能力边界。
- 已给出需求编号、模块职责、数据字段草案、状态语义和结果状态。
- 已提供通用业务输入及人工见证，明确它们不是自动规划结果。
- 已安排独立穷举、变异流程、反馈与端到端实验。
- 已检查文档链接、JSON语法、示例人工见证及相关现有回归。

本阶段不以“规划器运行成功”为完成条件；规划器属于第三阶段。检查记录见review.md。

## 通用场景及人工见证

示例见examples/document-workflow.json，场景为文档收集、审批、发布和确认。两个发布动作具有相同状态效果但不同能力需求，用来检查“相同最终状态不能直接合并”的要求。

| 场景 | 人工见证 / 预期 | 研究目的 |
| --- | --- | --- |
| basic | collect→approve→publish_standard，或发布替代动作 | 从状态与活动条件组合流程 |
| verified | 在发布后加verify | 目标变化导致活动增加 |
| collected | approve→publish_standard | 初始条件减少必要步骤 |
| already_done | 空流程 | 长度0的合法性 |
| mandatory_verify | verify | 初始达标仍须发生指定活动 |
| too_short | 最大长度2，没有合法流程 | 有界无解而不是全局无解 |
| unknown_source | collect前置条件未知，无法得到已证实流程 | 不将未知当true或false |
| feedback_fallback | standard外部拒绝，backup可被继续尝试 | 同状态序列保留与恢复搜索 |

人工最短见证不等于实现承诺首解必为最短。枚举模式应保留边界内所有合法序列，包括已达目标后的合法延长；长度与重复限制明示。

## 对照与指标口径

固定模板对照使用与规划器相同的活动语义和检查条件，提前冻结模板集；不通过弱化模板校验让新方法虚假占优。独立穷举器不能调用待检搜索器或其状态转换实现，按全部有限序列重放得到参考集合。

覆盖率=与参考可行集交集数/参考可行集大小，仅完整枚举且参考集非空时计算；参考集为空时记N/A并比较双方是否均为空。首解成功率只在已知可解且给定预算的测试集计算，另报预算与无解识别。验证通过率不单独作为质量证据，必须同时报告错误流程识别率与正确流程误拒率。

数值误差、运行时间与搜索规模分别记录；固定实例顺序和环境。小规模全部一致不证明任意规模的完备性。端到端通过率按逻辑层、接口层及外部层分层统计，不能把unsupported_mapping记成规划逻辑失败。

## 风险及控制

1. 状态空间爆炸：有限实例化、长度与工作量双边界；先小例再扩规模。
2. 过期推导：静态知识与动态状态分离，派生结论重算。
3. 共用错误：验证器独立语义实现、变异流程及穷举对照。
4. 接口错配：显式支持矩阵，不把通用活动强制变成旧三角色。
5. 反馈过度泛化：候选与外部上下文绑定，首版只排除确切候选。
6. 科研口径：本阶段完成设计，不声称新算法、实际资源调度或真实任务验证已完成。
