# 审查结论、发现与结论范围

## 审查对象

生产代码基线4ea1145，覆盖前四阶段。使用23组集中验收、混合模型三方对照、可控生成器故障注入、重复运行及既有回归。机器记录和源文件摘要见[审查报告](phase1-4/report.json)，输入、预期、实际和通过标准见[逐项清单](phase1-4/acceptance.md)。

## 发现与处理

| 发现 | 处理 | 性质 |
| --- | --- | --- |
| 第一阶段表只有需求到设计/后续验收，缺少当前实现与具体测试映射 | 增加持续追踪表，逐项列明R01～R12及未验收内容 | 证据链补齐，不是规划算法修改 |
| 既有通过数量分散在阶段说明，缺少同一次审查的有效输入、预期与实际记录 | 保存23组记录、调用时的真实模型/序列、每次完整搜索统计、环境、源摘要和完整回归日志 | 复现与可检查性补齐 |
| 文件分离与Mock隔离还不足以说明能抓住生成侧的真实错误 | 注入“目标判断永真”和“绕过前置条件写入成功状态”两种故障，独立验证器均拒绝 | 对执行独立性的附加有限证据 |
| 新审查工具最初允许零个/负数模型或bool作为模型数量，可能形成空研究假通过 | 添加1～128精确整数约束；9项工具测试含该回归，以及完整搜索报告留存、失败传播、证据修改和来源变化检查 | 审查基础设施缺口已修复；不是前四阶段生产算法缺陷 |
| 外部适配/反馈虽已设计，尚未实现；不能随前四阶段一起标为完成 | R09未验收，R10/R12仅部分覆盖；C19明确保持external_status=not_run | 研究范围澄清 |

本轮没有修改task_flow生产模块、本体、旧design引擎、评分或FDNA公式。在本次声明范围内未发现规划器、重放器及独立参考的语义反例；这一结论不等于任意模型正确性证明。

## 本轮可支持的检查结论

- 所测三值表中，缺失/unknown不等于false；状态依据变化后派生结论重新计算。
- 多效果读取旧状态且失败不提交部分更新；冲突写入、域外对象和版本不符被拒绝。
- 目标/初始条件变化会调整流程，空流程与强制活动分开处理，最终破坏目标的序列不通过。
- 完整枚举与恢复的集合在所测边界内一致；同终态但不同活动/能力的序列得到保留。
- 3次相同配置运行的非时间记录一致；输入重新排列保持语义序列，但来源摘要按约定变化。
- 错误流程与候选篡改被检测；验证器未调用被隔离的生成侧语义函数，并能拒绝主动注入故障。

错误识别实验分别统计4种错误流程、4种候选元数据篡改；7条人工正例作误拒对照。这些是预先列明的有限案例，不混合解释成一般错误检测概率。32个混合模型1410个原始序列的证据同样只适用于保存的输入与长度0～3。

32个混合模型中16个有已证实流程，共126条可接受序列；其余模型的空接受集合也参与三方对照，未只挑可解例子。23组专项检查、215项既有回归及9项工具测试的分母分别报告，不将它们相加当作研究有效性的分数。

## 不能由本轮推出的结论

1. 不能从有限枚举对照推出任意规模完备性、一般正确性或算法优越性；尚无此类形式化证明。
2. 独立指核心执行语义实现和独立参考；共享Schema、输入合法性检查和建模假设仍可能存在共同错误。
3. 明确边界内无解不同于实际任务不可能完成；有未知阻塞时只说明没有得到已证实方案。
4. 软件测试通过和逻辑验证通过不证明研究新颖性、外部资源可落实或完整系统有效。
5. 新流程到旧能力/装备接口、十五目标完整新流程组网、多装备协同及动态资源调度仍未验收。

## 后续优先项

先将本轮证据作为可追踪基线保留，再进入第五阶段；第五阶段需明确能力映射、兼容性失败、反馈上下文和完整端到端验收。正式论文实验应在独立的新场景中补模板对照与规模分析，不将本次已查看的小例继续当作未见测试集。
