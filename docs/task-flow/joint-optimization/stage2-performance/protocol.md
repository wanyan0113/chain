# 阶段二受控性能基线协议

本轮仅建立性能基线，不修改生产搜索、候选身份、评价公式、资源约束或验证器。不新增分支。阶段一按用户评审关闭，JV-AUDIT-001保留为已修复问题；跨平台和领域有效性仍待验证。

## 变量与边界

| 组 | 单独变化 | 固定条件 |
| --- | --- | --- |
| P1 | 等效备用解析活动的数量1/2/4 | 单任务、法器库、指标及长度边界固定；每个替代活动具有独立身份 |
| P2 | 全部法器实例复制倍数1/2/3 | 单任务、活动库固定；复制属性、上下文及连接，改变可分配实例数量 |
| P3 | 附加OWL子类链长度0/32/128 | 单任务、规则及法器固定；最底层放置一个具名实例，不改变业务能力 |
| P4 | 同时开始的任务数量1/3/5 | 复制T1结构化任务，共用同一法器库，容量与库存固定 |
| P4冲突 | 三任务下非消耗资源容量降为1 | 任务数和候选生成条件固定；不自动错峰或调度 |
| P5 | 流程、分析、链生成和网络节点预算 | 原三任务验收数据、评价政策、开始时间和资源条件固定 |

P3是受控分类层级探针，不能代表任意OWL公理、规则交互或推理困难度。P4超过资源能力时可以正确无解，不因无解耗时较短得出算法扩展性提升的结论。各组规模不构成大规模生产能力证明。

## 运行和记录

每档至少5次，顺序执行。每次新建Python工作进程；每次真实推理由原适配器启动独立Python推理进程和HermiT JVM。没有持久JVM或应用缓存，因此只记录进程冷启动；操作系统文件缓存及其他桌面负载不可控，不宣称操作系统级冷启动或热缓存收益。

运行前冻结全部输入文件、知识摘要、环境、预算、工具和生产源码摘要。记录Python、Java、依赖、HermiT jar摘要、操作系统、CPU及内存；环境读取失败保留原因，不用伪造值替代。

主计时覆盖 `run_joint`，不含工作进程导入、独立穷举参考和文件序列化；另记工作进程整体耗时及业务报告字节数。流程搜索、重放、映射、候选生成、OWL、归一化、网络搜索、独立核验分别记录调用次数及每次时间。候选生成包含OWL，阶段时间有嵌套，禁止直接相加。OWL时间包含输入序列化、Python/JVM启动、推理和结果读取，不冒称纯HermiT计算时间。

Windows工作集按20ms目标间隔采样，覆盖工作进程及发现的子孙进程，包括Java。记录Python峰值、进程树工作集和各阶段观测峰值、阶段前后Python工作集差值。采样有额外开销、实际间隔不保证精确；进程树求和可能重复计入共享页，也可能漏掉极短峰值，因此不称为操作系统精确峰值或纯业务内存。

不支持的原始统计以缺失/null明确表达，不从耗时推造次数。流程节点、拒绝原因、链生成节点、去重数及网络剪枝直接引用生产统计。可行网络数如为访问到的叶子数量，保留其 `counts_scope`，不能当作全空间计数。

网络节点统计遵循现有实现，包含触发超限检查的尝试节点，因此节点上限1/8可显示nodes为2/9；该最后节点没有进入约束检查或完整组合评价。`evaluated`和终止原因另存，不能据nodes推断实际多评价了一个网络。

## 正确性与验收

测量工具需检验各实验轴隔离、输入不被修改、加测量与普通运行的候选集合、评分及网络一致。每个完成的重复运行对比确定性语义摘要；运行ID、证据ID和计时不进入该摘要。完整且可行的小规模案例与独立穷举参考对照，预算截断案例不强行对照完整候选集合。

记录流程和链完整性、网络证明状态、核验状态、是否有可行解及所有预算终止原因。核验未执行必须与核验通过区分。时间预算超限或异常进程的原始日志保留，未得到的流水线耗时等字段为null；不得把这些运行作为完整结果参与中位数。

没有预设加速倍数。通过意味着基线可追踪、相同配置语义可重复、有限参考一致、超限状态诚实、未改变业务语义。算法改进、热启动/缓存实验、跨平台比较及实际精度模型验证均在本轮之后。
