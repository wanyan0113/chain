# 跨流程联合优化验收矩阵

基线：[TFDO-DESIGN-1.0](design-v1.md)。状态：验收计划，全部待实施；下表不是当前测试通过记录。

## 1 身份与证据

| 编号 | 场景 | 必须满足的预期 |
| --- | --- | --- |
| ID-01 | 同活动流程、不同法器绑定 | candidate_id不同 |
| ID-02 | 不同活动流程、相同法器 | candidate_id不同 |
| ID-03 | 同候选在同次运行重复生成 | 候选实体合并，全部生成/验证证据保留 |
| ID-04 | 资源库存或可用性变化、本体不变 | design_context_hash及对应候选身份变化 |
| ID-05 | 只改候选输出显示编号或发现顺序 | candidate_id不变，不以运行序号判身份 |
| ID-06 | 相同输入重复运行 | candidate_id及集合摘要复现；run_id不同、证据独立 |
| ID-07 | 活动顺序或任一参数绑定改变 | flow_id和candidate_id改变，即使终态相同 |
| ID-08 | 同活动ID/版本下前置条件或效果改变 | 活动语义摘要改变，不复用原流程身份 |
| ID-09 | 重复同一活动、每次绑定不同法器 | 按环节出现位置保留完整绑定，不被角色字典覆盖 |
| ID-10 | 输入对象键顺序改变，集合字段记录顺序改变 | 规范载荷一致时身份一致；有语义的数组顺序不可排序消除 |
| ID-11 | 相同ID关联不同规范载荷，或同政策指标不一致 | 报告冲突并阻塞，不任意覆盖 |
| ID-12 | 只改预算、输出目录、显示排名或权重 | 候选实体身份不因这些运行/评价字段变化；评价证据相应更新 |
| ID-13 | 修改基础知识文件或映射语义 | 对应上下文摘要变化；不能复用旧上下文拒绝结论 |
| ID-14 | 非有限数、单位缺失或规范化键冲突 | 明确拒绝，不静默规范成另一份输入 |

## 2 集合与评价

| 编号 | 场景 | 必须满足的预期 |
| --- | --- | --- |
| EV-01 | 同任务的多个流程产生候选 | 使用同一个冻结候选集合的极值评分 |
| EV-02 | 加入时间极端候选 | 新建集合版本并重算全部评分；10/20加入100时，时间分为1、8/9、0 |
| EV-03 | 任一指标max=min | 该指标所有候选统一0.5，不能除零 |
| EV-04 | 单个候选 | 三项按统一退化规则，保留极值与原因 |
| EV-05 | 某任务无候选 | 不进入有效整体评分，不删除该任务继续报完整网络 |
| EV-06 | 已纳入候选缺原始指标或单位不一致 | 明确阻塞相关评价，不补0.5、1或原文案例指标 |
| EV-07 | 生成阶段已有临时分数 | 临时分数不得用于不可逆排除；冻结后统一生成最终评价 |
| EV-08 | 同候选、不同权重或不同集合 | 候选身份保持，评价上下文不同；历史分数不能直接横比 |
| EV-09 | 一探知、两协调、一具现 | 按显式sequential_product_v2政策手算时间、精度、成本一致，不解释为概率 |
| EV-10 | 任意拆分同一协调过程、重复赋总精度 | 领域模型审查发现重复计量风险；形式测试通过不冒充业务有效 |
| EV-11 | 近似相等但不精确相等的浮点指标 | 使用声明的算术/相等策略，不被不同模块私自isclose |
| EV-12 | 输入同一指标使用不同单位 | 不隐式混算；需要显式一致单位或另行版本化转换政策 |

## 3 联合资源与优化

| 编号 | 场景 | 必须满足的预期 |
| --- | --- | --- |
| OP-01 | 局部高分链争用独占资源 | 排除冲突，选择整体最优可行组合 |
| OP-02 | 局部低分链能解除其他任务冲突 | 候选保留，不因流程内排名低而误剪 |
| OP-03 | 更优网络来自非首个可行活动流程 | 新模式实际选出该网络；统一基准下优于快速模式 |
| OP-04 | 同任务不同流程原有评分参照不同 | 不比较旧分数，跨流程合并后重算 |
| OP-05 | 小规模完整穷举对照 | 可行组合、最优值、同分选择及资源核验与独立参考一致 |
| OP-06 | 分支定界未访问全部完整网络 | 若有可靠证明可标最优；保留剪枝和上界证据，不能把访问数当全体数 |
| OP-07 | 新增支配剪枝 | 不误删资源/时段有价值候选，不改变声明归一化范围；逐项对照参考 |
| OP-08 | 调整整体时间或成本报告 | 不改变原网络目标含义；报告字段不冒充独立优化目标 |
| OP-09 | 容量、库存、冷却、资源组、依赖或表10边界 | 延续旧约束语义并有严格边界反例 |
| OP-10 | 全部任务候选有链，但组合均冲突 | 报冻结候选集不可行，不未经覆盖证明扩大为全域无解 |

## 4 覆盖与证明

| 编号 | 场景 | 必须满足的预期 |
| --- | --- | --- |
| PF-01 | 流程、链生成和网络优化均完成证明 | 仅在全部声明边界覆盖及相关未知解决时标bounded_global_optimum |
| PF-02 | 流程或链生成超限，冻结合格子集 | 可求candidate_set_optimum；flow/chain coverage仍partial，全域不证明 |
| PF-03 | 网络搜索超限，有已验证当前最好解 | 只标feasible/incumbent，不报候选集最优或全局最优 |
| PF-04 | 网络搜索超限，无可行解 | 未定，不报无解 |
| PF-05 | 流程存在未知分支或不支持映射 | 已知子集结论可以保留，但不据此声称全边界最优/无解 |
| PF-06 | 候选集合或上下文在评分后改变 | 旧评价失效；集合变更新建版本，运行期间外部知识变化停止 |
| PF-07 | 全覆盖且无可行网络 | 有证据才标bounded_global_infeasible，不能仅靠未找到解 |

## 5 验证与兼容

| 编号 | 场景 | 必须满足的预期 |
| --- | --- | --- |
| VR-01 | 篡改流程、终态、法器绑定、指标或最优性标记 | 独立核验拒绝相应不一致，不信任passed字段 |
| VR-02 | RDF和报告 | 活动流程、候选身份、逐环节法器及来源可追踪；严格静态检查 |
| VR-03 | 部分搜索当前最好解导出 | 与已证最优设计状态/文件契约明确区分，不伪装complete |
| VR-04 | 原快速模式、模板、评价模式和通用服务入口 | 原有行为及声明范围不变，历史实验不重写 |
| VR-05 | 全流程复现 | 相同规范输入得到同候选集合、原始指标和确定性最优选择；运行身份和耗时可不同 |
| VR-06 | 评价政策业务有效性 | 单独给领域数据/审查结论；没有时保持pending，不因算术正确自动通过 |

## 6 验收证据要求

每项记录输入夹具、政策/算法版本、独立预期、实际输出、断言、候选集合与上下文摘要、运行身份和证据位置。测试实现不得仅复用被测评分或资源判断作为唯一预期来源。

完成WP后逐项更新独立验收记录，不在冻结矩阵中把“预期”改写成历史“实际通过”。本设计冻结时无新增模式运行结果，也没有原始精度业务有效性结论。
