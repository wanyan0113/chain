# 装备组观测数据契约1.0

本轮冻结的是**软件数据契约**`team-observation-contract-1.0`：字段、身份、关联、缺失/重试、分母、配对、研究冻结条件及后续验收规则。冻结文件见[契约正文](team-observation-contract-v1/contract.json)、[数据Schema](team-observation-contract-v1/schema.json)、[研究协议Schema](team-observation-contract-v1/protocol.schema.json)及[内容封存清单](team-observation-contract-v1/freeze-manifest.json)。修改规范需新版本；不回写已发布清单。

**具体研究实例仍未冻结。** 方法、事件定义、真实装备版本、环境与执行顺序、样本划分和验收阈值尚未补齐，因此研究模板继续为draft/uncollected。此轮未实现导入器、数据独立核验器或研究锁定程序。Schema结构通过不等于来源关联、研究就绪或领域有效性通过。

## 一、三层观测与三层登记

此前四张CSV只是讨论用空表头。本版将登记拆成三表，防止整次执行或环节尝试消失后无法识别；原草案和历史证据保留。

| 表 | 一行代表什么 | 身份与主要关联 |
| --- | --- | --- |
| `samples` | 一个预登记基准样本 | `sample_id`主键；总体、任务、cluster、split、stratum、配对ID及基准输入 |
| `executions` | 样本在某实验臂的一次整链执行 | `execution_id`主键；关联样本、实验臂、源报告与候选；登记环节顺序、环境、执行重复编号及计划/实际顺序 |
| `stage_attempts` | 一次执行中某环节的一次尝试 | `(execution_id, stage_instance_id, attempt_id)`；包括未到达、未执行、失败、完成和原因 |
| `member_observations` | 某成员在一次环节尝试中，对一项负责能力的贡献观测 | 全研究唯一`observation_id`；关联样本、执行、候选、环节、尝试、成员、版本、能力和输入来源 |
| `group_outputs` | 一次环节尝试的整体输出 | 独立`observation_id`；关联同一次尝试的成员观测、汇聚者、组级输出及独立参考 |
| `task_endpoints` | 一次执行对预定义任务终点的独立评价 | 独立`observation_id`；关联执行与终点事件，独立保存实际结果及参考 |

所有观测ID还须跨三张观测表全局唯一。环节身份按执行与实例识别，两个decide不合并。成员承担两项能力时分别记录两项贡献，但不能把它们算作两个独立样本。成员、组和终点的标签分别评价，禁止相互推算生成真值。

每条观测保存实际标签、参考标签、输出引用、独立参考、评价方法、观测/参考状态、缺失主原因及详细说明。当前1.0仅冻结**分类标签与`categorical_equality_v1`**；连续测量可保留在外部原始引用中，转换为事件标签的规则必须事先定义，暂不增加连续误差评分。

## 二、身份、版本与来源

- 研究协议绑定源报告内容哈希、精确候选、活动实例、成员/能力分工、汇聚者及实际版本。源报告须经已有独立可行性/优化核验；该核验不证明统计模型或设备效果。
- 草案基线`source_binding`不代表所有其他来源。多报告实验臂按`source_report_id`分别解析`source_reports`中的内容哈希，再核验候选与任务。
- 同一基准样本的两个实验臂使用相同`sample_id`/`pair_id`，但有不同`execution_id`。`execution_repeat_id`区分预定义的整链重复；重试则使用同一执行内的`attempt_id`。重复和重试都不是新增独立样本。
- `samples`冻结总体、任务、cluster和校准/评估分组；同一主体/cluster不得跨校准与评估泄漏。执行身份、实验臂、顺序、重复次数在看见结果前登记，不按结果重新分组。
- 后续输入必须匹配源候选和实际装备版本。`UNASSIGNED`只用于研究模板，不能充当已知实测版本。
- JSON元数据明确`study_id`、`protocol_revision_hash`、`data_origin`；CSV必须随附同样元数据和完整六表文件映射。只有表头不能识别数据集或协议版本。

软件清单哈希针对精确文件字节；生成器固定JSON为UTF-8/LF、CSV为UTF-8/CRLF，并以Git属性保留封存包原始字节。研究协议和源报告哈希按`task_flow.joint_identity.canonical`的规范JSON计算，不能混用原始文件字节摘要。登记计划按主键排序后计算指定字段投影哈希；活动顺序数组保留语义顺序。精确规则见契约正文`hashing`和`lock_plan_projections`。

## 三、漏失、失败、重复和重试

每个已分配执行都应登记源候选的全部预期环节及首次尝试，未进入后续环节也不删除。每次登记尝试都有预期成员能力和组级观测槽位，缺行与明确缺失分别报告。

尝试从1连续编号，不超过冻结的最大次数；注册先于尝试开始，同一环节尝试不得重叠。失败重试追加记录，禁止覆盖第一次。实际运行状态、时间及环境有独立审计轨迹，不回写冻结的分配/顺序投影。

本版分析统一选**首次登记尝试**。不挑最好一次，不因第二次成功而替换第一次未知/失败结果。整链重复执行按预定义重复编号保留，分析须考虑同一sample/cluster的相关性。

运行失败不自动等于分类标签错误。若预定义事件把运行失败判定为失败，仍须记录独立的事件标签和依据；没有输出或真值时保持未知，不补0/1。组级标签完整而成员记录丢失时，保留组级描述性结果，同时阻塞依赖完整成员来源的核验，不用成员未知状态制造组级失败。

最终任务终点按预定义时间窗独立记录，可包含重试效果；它不必等同首次尝试的环节成功交集。若下游实际消费了上游第二次尝试的输出，要保存实际来源引用；与预先定义的分析尝试链不一致时，不进行该条件模型的合格预测验证。

## 四、分母和概率解释

按环节实例、成员、能力、版本分别报告登记/分配、进入、尝试、记录、真值已知、可评价、正确和缺失。样本、完整配对、单环节可评价集合不可互相替代。独立任务终点也单独报告入组与可评价分母。

首因子使用预定义队列的无条件事件率。后续条件概率仅在**同一队列、全部前序预定义组事件成功**的样本上计算，并报告分子、分母及前序未知样本。只检查相邻环节成功不够；不能用另一队列的条件率补齐本队列。

条件分母为零时为null，不补0或1；联合事件本身仍可另行直接计数。完整前序条件链式法则不需要独立性；边际率直接相乘需要相应独立性依据。还须分别检查任务成功事件是否等同全部环节成功。

同队列条件率的比例约消只验证恒等关系，不验证新样本预测。模型估计/选择使用校准集；误差、区间、分组与系统偏差验收使用独立评估集。真实测量可比性、概率/因果解释和阈值合理性不由Schema或哈希证明。

## 五、短长流程配对和环境控制

配对单位是同任务、同总体中的同一基准样本；实验臂可具有不同流程长度或成员配置。不能把当前T1、T2这样的不同任务自动配成短/长流程。

事先定义分配/随机化或顺序平衡方法，保存计划顺序和实际顺序、偏离原因、环境层、原始环境记录、复位/清洗或残留控制证据。重复执行按样本与预定义重复编号配对，但不作为独立主体。配对本身不证明消除了时间、学习、环境变化或前次执行残留。

报告登记对数、完整对数、缺失对ID、双向改变计数和完整配对描述差；不隐去缺配对。独立组设计必须另行预定义，不能事后造配对。分层、聚类、样本难度和完整率均需检查。

## 六、实际研究实例何时才能冻结

1. 补齐成员逐能力、组级输出和任务终点的测量对象、方向、量表、分类事件、方法和独立参考；先完成领域可比性评审。
2. 绑定所有来源候选及真实设备/固件版本，明确实验臂和相同基准样本的可执行方案。
3. 事先填写校准/评估分组、最大重试、计划整链重复次数、终点窗口、顺序/环境/残留控制。
4. 冻结最低校准/评估/前序条件支持数量、置信水平、允许误差、分组和系统偏差规则。配对设计的最低评估数量指合格配对；缺失率另行报告，不能仅满足完整案例数就忽略漏失。
5. 在评估输出产生前封存协议、基准队列、执行分配和首次尝试槽位的投影，生成含版本、内容摘要、时间及评审证据的不可改写研究锁。后续重试按已冻规则在开始前追加登记。
6. 协议、成员、事件定义或分配发生实质变化时，新建修订与锁，不编辑旧锁。历史数据按原协议保留，不自动迁移语义。

本轮只提供上述规则和结构Schema，**研究就绪检查、交叉来源/外键/时序核验及写入研究锁的程序尚未实现**。协议Schema可以拒绝明显未填的frozen声明，但即使字段齐全，也不代表已真实完成研究冻结或领域评审。

## 七、验收与下一步
