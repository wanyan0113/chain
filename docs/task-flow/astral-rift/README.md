# 星界裂缝：多节点动态稳定流程生成与验证实验（实施版）

本文件补全用户提供的修订稿，作为本次测试依据。所有对象、能力和延迟均为虚构合成数据；S/D/A仅为活动类别，不接入旧链网系统，不代表资源节点分配。本案例只检验有限、确定性、有界顺序流程。

## 1. 对象、事实和初始状态

唯一对象为`rift-01`，所有活动参数`rift`均绑定该对象。正常初态如下；所有事实显式提供，null表示未知而非false。

| 事实标识 | 含义 | 类型/初值 |
| --- | --- | --- |
| rift_exists | 存在待观测裂缝 | 静态布尔，true |
| can_stabilize | 允许执行稳定措施 | 静态布尔，true |
| anomaly_known | 异常信息已获取 | 可变布尔，false |
| state_verified | 裂缝状态已核验 | 可变布尔，false |
| energy_logged | 能量变化记录已获取 | 可变布尔，false |

## 3. 历史状态一致性

本轮统一采用历史完成状态解释，不使用外部成果导入来跳过历史事实。已核验必须同时已有异常信息；已分析必须已核验；已确定方案必须已分析；已稳定必须已有方案；已确认必须已稳定。能量记录依赖已核验，观测判断依赖能量记录。

变化初态时，案例数据显式给齐所需历史事实，不由生成器偷偷补齐。数据适配拒绝“子成果为真、历史依据明确为假”的快照；同样的历史依赖还编码为模型禁止条件，由独立验证器检查。历史依据未知时不能凭空认定一致。

elapsed_seconds只计本次待生成流程的工作，不累计初态中已完成历史的未知耗时。can_stabilize约束新的A1执行，不用于追溯否定已经完成的历史稳定状态。

## 5. 搜索及延迟边界

正常配置：最大长度8、最大尝试节点20000、搜索时间预算30000ms、每活动最多一次。长度是上限，不要求用完所有活动。节点数按实现中的“尝试活动实例次数”统计，不叫不同状态数量。

正常任务仅统计延迟；60秒数值上界大于全部八活动总和27秒，不是业务优化目标。延迟边界实验额外加入elapsed_seconds超过业务预算的禁止条件，每一步及最终状态均检查。T3预算22秒应可行，21秒应在完整搜索后报告边界内无已证实流程。

搜索墙钟预算与合成活动延迟分开记录。时间超限分类使用确定性测试时钟触发，记录clock_kind，不能把其elapsed_ms当作真实性能测量。

现有搜索为迭代加深；本实验另用独立枚举核对T1～T3的最小活动数与最小合成延迟。结论仅限此固定模型，不宣称一般最短延迟规划能力。

## 7. 独立验证和枚举对照

验证器从原始目录、请求和活动实例重放，不信任声称的最终状态。构造7组拒绝探针：未获取即核验、缺方案即稳定、禁止条件下稳定、缺稳定即确认、重复活动、域外参数、篡改候选最终状态。另保留T1加S3/D3的合法延长作正例，检查不会误拒。

对正常T1～T3分别完整枚举。独立领域参考不调用生产的条件、效果、落地或搜索函数，直接从本页规则逐条重放全部不重复活动序列。八个活动长度0～8的不重复原始序列共109601条，每个任务分别检查。比较完整活动实例序列集合，逐个独立验证所有生成候选，同时核对累计延迟。

双方仍共享给定规则和初始数据，不代表独立领域人员已确认规则完整。该案例没有运行外部服务接口或资源调度。
