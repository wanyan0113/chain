# 独立领域需求复核包（待人工执行）

状态：**尚未完成独立人工复核**。本包由原开发助手整理，不能把材料准备、自查、模型测试或另一轮助手回答计作独立领域人员意见。本轮没有联系或替任何人签署复核结论。

对象是冻结提交9e3635a中的合成报销审批模型。这里可以复核“模型是否准确表达已给定的合成规则”；真实财务需求的完整性仍须实际制度和有资质的业务负责人提供依据。合成政策不能代替真实制度。

## 建议执行顺序

1. 选择未参与本轮建模和检查器编写的复核人，记录其角色、相关经验和独立性声明。
2. 先只阅读A包：[原始需求](phase-a-requirements.md)与[原始业务输入](phase-a-raw-cases.json)。独立列出必须条件、完成条件、异常处理和未规定事项；暂不阅读模型或现有实验结论。
3. 将该列表固化为第一轮记录，然后阅读B包中的活动目录、请求和字段映射，逐条比较，不先以模型字段反推需求清单。
4. 对遗漏、歧义、冲突、范围排除及原始数据不足分别记录；允许“无法判断”，不要求全部同意。
5. 由开发方和复核人共同确认如何处理分歧。需要修改时，先更新需求版本，再更新模型、独立检查规则和测试；保留旧版及反例。

B包见`phase-b-models/`，使用新虚拟环境中的冻结适配器生成，仅包含输入文件，没有调用真实业务系统。材料生成不等于独立复核通过；新环境验证另见[重建报告](../rebuild/README.md)。

填写[复核表](review-form.md)，由实际复核人补齐身份、日期、独立需求清单、逐项判断和分歧处理。未填写之前，`review-status.json`必须保持pending_human_review；材料或自动测试通过不能自动改为人工通过。
