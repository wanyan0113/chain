# A包：原始合成需求

请在第一轮独立需求列表完成前，不阅读生成模型、独立检查器代码或既有实验的预期结果。以下是研究中给定的简化政策，来源为研究者构造，不是现实企业制度或法律。

## 业务目标

根据一到两个报销单的当前记录，组织后续审批活动，使请求指定的报销单达到“记录授权”或“完成归档”的状态。只生成和检查模拟流程，不执行付款、远程审批或真实授权。

## 已明确的业务规则

1. 金额以人民币整数分记录，金额必须为正。金额比较不能把元与分混用。
2. 新提交报销单前，票据有效性必须明确为真。未知不按有效处理，也不自动等同于已知无效。
3. 审核必须发生在提交之后。可以自动审核或人工审核，两者完成相同的“已审核”状态，但依赖不同服务。
4. 记录授权前必须已经审核。金额不超过100000分时，不要求增加经理审批；金额超过100000分时，记录授权前还必须已获经理审批。
5. 经理审批要求已审核，高额要求按每个报销单自己的金额判断，不借用另一报销单的审批。
6. 归档前必须已经记录授权。如果请求只要求授权，不强制归档；如果请求要求归档，最终状态必须归档。
7. 已明确完成的历史步骤可以作为初始状态，不应为凑固定阶段重复执行。初态已满足请求时，允许空流程。
8. 多个报销单的身份、状态与目标分别保持。一个单据达标不代表另一个也达标。
9. 服务状态可能明确可用、明确不可用或未知。逻辑流程成立不等于服务条件满足；某个服务不可用时，可以检查其他合法活动序列。
10. 搜索有明确的流程长度、节点数和时间边界。超限或信息不足不能直接解释为现实业务无解。

## 已声明的范围排除

仅限合成数据、有限对象、确定性顺序活动、整数金额；不包含真实资金流、税费、汇率、身份权限、发票去重、动态容量、并行审批、实时重规划或完整企业制度。

- 从上述文字提取您认为必须建模的前置条件、效果、历史一致性和最终条件。
- 哪些规则边界有歧义，哪些额外要求完全未被指定？请将两者区分。
