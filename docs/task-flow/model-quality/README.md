# 通用原型冻结与模型质量专项审查

研究定位：如何基于结构化任务需求、活动前置条件与执行效果，动态生成满足目标约束的有界顺序流程，并通过独立验证和外部条件检查提高流程生成结果的可信度？

本轮冻结已有通用原型，并补充只读模型质量审查，没有修改规划器、独立验证器、原系统算法或本体。模型审查采用明确给定的合成报销规则，不能自动判断任意业务需求是否完整。

## 2. 只读模型审查方法

```powershell
.\.venv\Scripts\python.exe -B -m workflow_tools.model_quality_audit run --output-dir generated/task-flow/model-quality-1
.\.venv\Scripts\python.exe -B -m workflow_tools.model_quality_audit verify --output-dir docs/task-flow/model-quality/evidence
.\.venv\Scripts\python.exe -B -m unittest tests.test_model_quality_audit
```

审查器保留原始请求，明确另建枚举用的有效请求；不回写基线。流程仍受原长度、节点、时间预算限制，另设至多100个候选的审查上限。每个候选先独立逻辑重放，通过后才用原始业务数据执行独立领域检查。报告保留原始数据、目录/请求、形式验证轨迹、领域反例、搜索覆盖和终止原因。

| quality_status | 含义 |
| --- | --- |
| invalid_model_contract | 已违反系统明确编码的模型契约；不等同于任意业务语义审查 |
| counterexample_found | 至少一条形式成立的流程违反给定独立业务规则；反例成立不要求穷尽其他候选 |
| no_counterexample_within_bounds | 声明边界内完整枚举、有实际已验证候选、无未知阻塞，且相对该业务规则未发现反例 |
| inconclusive | 无流程、未知、预算不足或候选未获独立认证，均不颁发模型质量结论 |

no_counterexample_within_bounds不是“模型正确”的证明。摘要始终保留model_quality_proven=false；实验expectations_met只表示观察到了预先列明的行为，包括发现问题和无法判断。

## 3. 13个检查及实际结果

[审查摘要](evidence/summary.json)、[逐项证据](evidence/quality-probes.json)。本轮变异全部为主动注入，不是宣称发现5个生产缺陷。

| 检查输入 | 实际观察 |
| --- | --- |
| 原始高额、低额两组正例 | 完整枚举，在给定独立规则和边界内未发现反例 |
| 删除高额经理审批要求 | 找到形式通过、领域规则拒绝的流程 |
| 金额阈值放大100倍 | 找到金额政策反例，暴露单位/阈值误用 |
| 删除有效票据前置条件 | 明确无效票据仍能形成形式流程，领域检查拒绝 |
| 遗漏业务最终目标 | 形式上允许空/不完整流程，原始业务目标检查拒绝 |
| 篡改初始状态为已完成 | 形式上允许空流程，原始业务状态重放拒绝 |
| 重复效果、派生循环、写静态事实 | 三种均由模型契约拒绝 |
| 相互矛盾的前置条件、未知票据、节点预算1 | 三种均为inconclusive，不把无候选当成模型质量好 |

两组原模型未发现反例只支持该固定策略和范围。独立领域检查器仍共享原始数据和简化政策假设；若政策本身错误、双方共同漏写规则，仍可能一致通过。工具测试还主动让领域检查器错误地总返回通过，确认这种情况下会漏检。该测试揭示依赖假设，不是检测机制已经解决共同错误。

## 4. 需求—模型—独立依据核对表

下表来源是明确标注的合成政策，不是法律或真实企业制度。把自然语言需求转成约束仍需领域人员审阅。

| 已声明需求 | 模型位置 | 独立检查/反例 |
| --- | --- | --- |
| 新提交必须有明确有效票据 | submit前置条件receipt_valid=true | 领域submit分支；omit_receipt_condition |
| 审核先于授权 | screened及eligible派生条件 | 领域authorize分支 |
| 金额>100000分必须经理审批 | eligible中的金额比较及manager_approved | 独立阈值比较；omit_manager_rule、wrong_threshold |
| 最终须满足原始授权/归档目标 | 请求goal按原始goal生成 | 独立原始目标检查；omit_business_goal |
| 不得把未完成输入当作已完成 | 字段映射、输入摘要与初始状态 | 直接从原始记录重放；altered_initial_state |
| 两个单据的身份分别保留 | claim有限参数绑定 | 既有双单参数混用拒绝测试 |

尚未声明的业务规则不能由本表“推理补齐”。本轮审查器用于研究评估，不是所有生产入口的强制检查；没有新增自动修复、伪造需求或扩大剪枝。

## 5. 能力映射与接口边界

[接口契约与检查记录](interface-contract.md)及[能力探针](evidence/capability-semantics.json)确认通用接口允许一活动多能力、一能力多活动，且多能力按合取而非任选解释。来源、版本、活动参数及完整逻辑验证上下文必须保留。
