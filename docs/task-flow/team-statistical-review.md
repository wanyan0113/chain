## 五个问题的回答

1. **装备组质量评价整体输出，还是成员贡献？** 两者分开。成员贡献针对其实际负责的能力，装备组质量针对该环节整体输出；任务终点还须另行评价。成员有能力、提供了输出，不等于组输出正确；组输出正确也不等于任务物理效果达标。
2. **成员分数能否映射到组级质量？** 当前不预设映射。若后续提出融合、冗余、互补或加权模型，需另给版本、适用条件、依据与实验；不能默认成员精度连乘。记录成员结果仍有诊断价值，但不能用来伪造组级真值。
3. **互补、协作与汇聚者纠错如何反映？** 记录成员输入/输出引用、承担能力、汇聚者、组级输出及来源关系。出现成员错误但组输出正确，只能描述“观测到恢复”；没有机制与对照依据时，不能直接称为汇聚者造成的纠错效果。
4. **组级与串行环节评价能否直接比较？** 共同量表ID与总体字符串仅是声明。还需审查测量对象、评价方向、量表的实际含义、方法和参考真值是否足够可比。第一阶段的能力通过和第二阶段的质量假设均不能替代这项领域审查。
5. **组级整体评价能否独立获得标签？** 应当如此。组输出与组级参考分别留存，最终任务结果与任务参考再分别留存；不能由成员标签的乘积或最后一个分类标签自动生成。

## 九组受控探针

参考统计器[team_statistics_reference.py](../../workflow_tools/team_statistics_reference.py)只依赖标准库，不调用生产评分、归一化、组队或网络优化。审查驱动另行调用已有生产语义检查，以确认其保护和未覆盖边界。

- **成员、组、终点分离**：10个合成样本中，成员A、B各对8个，边际率乘积约0.64；独立组输出对9个，独立终点对7个。三层结果保持分开。
- **相关边际与完整条件链**：三个完全相关事件各8/10成功。边际连乘约0.512，联合事件率0.8；条件分母为10、8、8，条件因子为0.8、1、1，连乘0.8。
- **纠错打破终点等价**：保留上述环节事件不变，另一个原失败样本的终点被模拟修复。联合事件率仍0.8，终点率为0.9，不能再把两种事件混同。
- **条件零支持**：前序无成功样本时，后续条件概率为null，不能补0或1。联合事件率仍可直接计数，但无法从该队列估计所有条件因子。
- **同样本同总体配对**：10对合成样本的短/长设计终点分别8/10与9/10，完整配对描述差为0.1，不声称因果效果已证实。
- **缺配对保留入组分母**：删去一个长组观测后，仍报告登记10对、完整9对及具体缺失ID；不把9对悄悄当完整研究总体。
- **更换配对总体拒绝**：某条长组记录的总体与登记不符，参考检查明确拒绝。样本身份变化和重复配对也有测试。
- **条件声明不要求独立性**：以“完整前序联合成功”为条件的声明可以使用概率链式法则说明，不被错误要求补独立性证明；仍不自动获得领域验证。
- **同量表不同构念**：现有字段可接受这种声明，但审查标记测量有效性pending，明确留给领域审查。

同一完整队列上，用逐级完整前序条件的经验率连乘得到联合经验率，本质上是计数比例的约消；它不构成对独立新样本的预测验证，更不能据此证明事件独立。后续应在预先定义的校准数据上建立模型，再用独立评估样本检查终点，并考虑聚类与重复执行。

## 来源绑定的研究草案

```powershell
.\.venv\Scripts\python.exe -B -m workflow_tools.audit_team_statistics --output-dir generated/task-flow/my-team-statistical-review
```

默认读取已归档的真实OWL核验后的1.1合成优化报告，也可用`--source-report`提供同类报告。输出包括：

- `audit.json`：9组探针结果、5项开放发现、源报告摘要及独立核验结果。
- `synthetic-fixtures.json`：单独标注synthetic_simulation的合成输入；不能当作真实采集数据。
- `protocol-draft.json`：从所选链提取环节实例、真实成员、能力分工、汇聚者及评价方案身份。未知装备版本保持UNASSIGNED，方法、测量对象、方向、量表和总体保留待填。
- 四张只有表头的`.draft.csv`：登记表、成员贡献表、组级输出表、独立任务终点表。用于讨论后续字段，不表示现有软件已经支持导入。

草案保留两个任务的8个环节实例及多成员组，不按decide类型合并。它不把T1和T2自动当成一个任务的短/长配对；两者本来就是不同任务。真正的跨长度试验还需同任务、同基准样本和相应不同流程设计，配对、执行顺序及残留控制均待明确。

草案的设计身份绑定所选候选、来源输入/上下文和评价上下文；单独改变运行ID不改变草案设计身份。成员版本、真实标签与研究定义尚未补齐，所以不生成“准备好统计验收”的状态。
