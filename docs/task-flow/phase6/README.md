本阶段交付通用合成场景下的实验程序、配置、原始记录和分析。旧能力/装备接口尚未接入，任务书中的完整旧系统端到端实验仍未完成。本报告不将通用实验通过解释为整个系统阶段验收完成。

## 实验协议与复现

```powershell
# 新目录运行；不会覆盖已保存证据
.\.venv\Scripts\python.exe -B -m workflow_tools.task_flow_study run --output-dir generated/task-flow/phase6-study-1

# 检查已保存证据与当前被审查源码的摘要
.\.venv\Scripts\python.exe -B -m workflow_tools.task_flow_study verify --output-dir docs/task-flow/phase6/evidence

.\.venv\Scripts\python.exe -B -m unittest tests.test_task_flow_study
```

[实验配置](experiment-plan.json)固定模型族、参数、重复次数、模板和各场景预期。驱动器先写有效plan.json，再执行实验；摘要见[summary.json](evidence/summary.json)。这是本地配置冻结，不是外部预注册或未见测试集。案例为人为设计的压力和差异见证，不能解释成随机任务总体样本。

新模型族是合成服务工单：progress为有限整数，每个阶段有若干等效处理活动，正常定义只能从i推进至i+1。单个工单、确定性效果、顺序执行；不包含设备、空间、连续参数、并行、实时调度或真实业务观测。它不同于先前的文档/计数输入，但仍是研究者构造的简单模型，不足以证明跨领域应用有效。

每个配置保存完整catalog/request、候选及验证轨迹；清单记录源码摘要（只规范化CRLF为LF）和证据的精确字节摘要。verify要求完整文件清单，并检查plan摘要。清单用于版本一致性和意外修改检查，不构成第三方认证，也不能防止同时伪造数据及清单。源码变更后旧证据不能自动代表新版本。

## 1. 小规模正确性

[correctness.json](evidence/correctness.json)包括8个模型、6808条原始序列，长度上限2～4、最多8个活动实例。独立参考逐条生成和重放全部原始序列，不调用生产条件、效果、实例化或搜索实现；生产搜索采用完整枚举，并对全部输出独立验证。

实际接受34条序列，生产集合与参考集合逐项相等、无重复，全部通过独立重放。此外，在这个特定模型族中，合法完整路径数可独立计数为width的depth次方，实际数量与该计数一致。

全部8个参考集合非空，声明范围内的集合覆盖为34/34。原始序列数不是成功流程数，也不能与前轮1410条直接相加作为方法得分。这些证据只支持列明输入和边界，不是任意长度、任意规则的正确性或完备性证明。

## 2. 固定模板覆盖对照

[templates.json](evidence/templates.json)使用同一份四阶段、每阶段两个变体的活动库。冻结四个模板：空流程、从阶段1开始的两步流程、从阶段0开始的三步流程、从阶段0开始的四步流程；全部使用v0变体。不在看到请求后裁剪、扩充或重组模板。

模板和生成候选使用相同活动定义、目标、必须活动约束及独立验证器。基线试完全部四个模板，生成器按首解模式搜索。此处比较覆盖，不进行运行时间排名。

| 统计口径 | 动态生成 | 冻结模板 |
| --- | --- | --- |
| 8个人工已知可解场景 | 8个求解且验证通过 | 4个模板适用且验证通过 |
| 1个必须活动与初态不兼容的无解场景 | 边界内无解 | 没有模板通过 |

差异场景分别为更短目标、较晚初始状态、必须使用另一活动变体等。模板未覆盖只说明这四个模板的局限；扩充模板可以改变结果。不能由8/8和4/8推导新方法普遍优于模板、外部资源可用或真实任务成功率。

## 3. 语法合法但定义错误的模型

[model-risks.json](evidence/model-risks.json)的6个模型全部通过JSON Schema结构校验。

| 人为缺陷 | 系统实际行为 | 支持的结论 |
| --- | --- | --- |
| 同步重复/冲突写入 | 语义契约拒绝 | 能识别已编码的效果一致性限制 |
| 效果写静态事实 | 语义契约拒绝 | 能识别已编码的只读限制 |
| 派生规则自循环 | 语义契约拒绝 | 能识别不支持的派生循环 |
| 同步要求progress=0和progress=1 | 搜索无流程；没有报告“模型定义错误” | 无解不等于已诊断矛盾建模 |
| 一步从0写到3 | 生成及独立验证均通过 | 未发现模型外的阶段跳跃错误 |
| 最后活动漏写前置条件 | 生成及独立验证均通过 | 未发现领域前置条件遗漏 |

后两例用报告中明确列出的人工领域要求“每步恰好推进一阶段”检查实际轨迹，发现违反。该要求没有提供给系统，因此验证器按已给定模型通过是形式语义一致，而非业务模型正确。

实验通过表示观察到了预期行为，包括预期的漏检；绝不是6个错误全部被系统识别。这直接说明三方一致仍可能共享错误建模假设。自动诊断任意不合理业务模型不在本实现能力范围内。

## 4. 效率与预算

[efficiency.json](evidence/efficiency.json)含10组配置、每组3次，共30次。每次重建问题及会话，采用相同首解算法；保存准备耗时、搜索调用墙钟、规划器内部耗时、独立验证耗时、节点数、候选、终止原因与边界。节点计数为尝试活动实例数，不是不同状态数。

| 变化项 | 控制条件 | 观察到的节点数 |
| --- | --- | --- |
| 活动实例3、6、12 | 目标长度3、无附加禁止约束；增加各阶段等效变体 | 15、33、87 |
| 必需长度2、4、6 | 固定同一12实例活动库；仅改变目标进度与最大长度 | 16、148、720 |
| 禁止约束0、8、32 | 固定6实例活动库、长度3；增加静态政策事实检查 | 均为33 |
| 节点上限2000 | 32实例、目标长度8、时间上限30000ms | 3次均在2000节点处超限，结论undetermined |

重复运行的非时间结果一致。中位数及最小/最大墙钟时间保存在原始记录；时间不要求字节复现。没有预热或随机化运行顺序，仅为同一机器的一次顺序测量；操作系统负载、解释器与缓存均可能影响时间，三次不足以作显著性判断。静态政策约束不会改变可行集合，主要测检查成本，不代表复杂动态约束。

这些数据说明在所测结构中增加活动变体、要求更长流程会增加搜索开销，预算仍必须保留；不能推出一般复杂度、任意大规模可用、时间严格单调或算法性能优越。正确性对照与效率实验分开，不因找出首解就声称完成枚举。

[相关回归日志](tests.log)和[研究工具测试日志](study-tests.log)保留实际运行输出。最终研究工具有11项测试，包括独立参考发现候选遗漏、模型错误未检出的负例、节点超限、固定长度轴活动库、空实验拒绝、结果失败传播及证据修改检测。相关回归在工具追加最后两项测试前运行，含当时9项研究工具测试；最终11项另行运行，两份日志计数重叠，不合并为研究分数。
