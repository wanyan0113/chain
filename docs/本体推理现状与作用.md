# 本体推理现状与作用

核对日期：2026-11-06。

已加入“知识外置、本体推理与规则推理协作”的首个可运行入口。配置 `knowledge` 后，HermiT实际参与设计前推理，任务分类、具名能力需求、法器分类及能力/协同关系回流业务流程。它不再只承担独立一致性检查。

## 当前分工

| 层次 | 职责 |
| --- | --- |
| 外置OWL知识 | 类、等价类、限制、具名能力和关系语义 |
| HermiT | 检查知识与实例的一致性及类可满足性，推导具名类型和所需关系 |
| 外置JSON规则 | 根据推导事实和原始参数核验目标适用性、距离等业务条件 |
| 设计程序 | 成链、评分、容量/库存/冷却核验及多任务选择 |
| 证据 | 知识快照、推理输入/结果、规则判断和设计报告 |

Protégé使用HermiT时执行的是同类OWL逻辑推理机制；程序现在也调用真正的HermiT。JSON规则是另一种显式条件推理，两者通过具名事实协作。数值计算和优化继续使用专用算法。

## 优势体现

虚构示例从目标类型推导目标类、任务类和具体能力需求，无需在Python编写目标名称分支；法器通过等价类得到角色和能力，再经过外置业务规则筛选。领域定义可以同时供Protégé和程序使用。

测试覆盖：改变场景目标类型后旧知识不能确认需求；只增加外部目标/任务类公理即可恢复设计；新增能力URI无需修改Python登记表；修改外部规则会改变可行性。知识变化会形成不同执行标识，旧报告不能继续用于导出。

因此，“场景或知识改变，通用程序不变”在已有事实字段、三种角色和运算符范围内已经成立。新物理模型、新输入映射或新角色仍需要开发。

## 边界

- 回流范围为具名分类及四种业务对象属性，不是全部OWL蕴含的完整物化；没有逐结论的最小公理证明。
- 等价类、交集、存在限制和具名值限制已有实际验证；SWRL入口和属性链专门验收尚未提供。
- 存在某种能力不等于确定某个具名能力；缺失事实不直接视为否定，缺失数值不自动补造。
- 未配置 `knowledge` 的旧输入保留有限继承/属性推导，不额外启动HermiT。
- 原文真实参数、来源矛盾和业务规则仍需逐项确认；工程示例不代表文章完整案例复现。

本步骤不需要AI API。下一步可将确认过的原文概念与规则逐项迁入外置知识，再用真实场景验收。命令、配置、Excel输入及输出说明见 [知识协作使用说明](../knowledge/README.md)。
