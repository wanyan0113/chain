# 本体推理现状与作用

核对日期：2026-11-06。

目前完成了本体推导参与静态链网设计的基础接入：类别、能力关系和协同关系的推导结果都能影响实际筛选与成链，不再只是设计完成后映射URI和导出RDF。这不等于完整OWL推理、全部原文规则落实或文章真实案例独立复现。

## 已完成的分工

| 层次 | 当前工作 | 实际作用 |
| --- | --- | --- |
| 本体知识 | 维护法器/能力类别、子类、子属性、逆关系、对称关系及规范能力个体 | 领域含义、分类和关系语义有统一来源 |
| 本体推导接入 | 执行命名类继承、子属性、逆关系和对称关系的有限正向推导 | 确定法器角色，提供可查询的类别、能力及协同事实 |
| 显式业务规则 | 任务→能力、能力筛选、表10数值比较与逐项解释 | 将需求和物理条件明确作用于当前任务 |
| 设计与优化程序 | 成链组合、评分、共享容量、库存、冷却及多任务选择 | 给出声明约束与目标函数下的最优可行方案 |
| 校验与追溯 | 结构/引用检查、静态本体检查、独立HermiT入口、来源与推导路径 | 区分输入错误、未知事实、不满足条件及逻辑一致性问题 |

这些角色互相配合。本体中存在某个概念或限制，并不自动证明某个具名法器具有某项业务能力；需要明确的事实或可执行规则作为依据。没有将匿名存在性限制转换为虚构能力、坐标、距离、库存或耗时。

## 本体优势如何体现

### 知识可复用

新增某种法器子类时，在主本体声明其父类，设计程序可以通过继承识别其角色。新增专用传讯子属性时，程序可以根据本体中的子属性关系识别其一般传讯含义。两者均有测试验证，不依赖新增Python分类分支。

### 关系含义统一

“某能力由某法器实现”与“某法器具备某能力”通过已有逆关系统一，不必维护两套人工事实。通用传讯关系的对称性来自本体，而不是在成链代码里无条件添加反向边。专用子属性不会因为父属性对称就自动反向成立，也不会从A与B、B与C传讯推断A与C直接传讯。

### 推导能影响设计

关系示例中的能力规则使用推导出的 `hasCapability` 事实，协同检查使用推导出的传讯事实与显式统筹事实。删除关键来源声明、标记来源疑点，或移除相关本体公理，会使相应能力/关系不能确认，设计被阻塞或输入不再满足关系契约。能力声明不免除距离、目标类型和资源核验。

### 过程可解释、结果可核对

报告保留声明、实际使用的本体公理、前提事实、来源、类别路径和使用位置。RDF导出针对当前输入及本体重新运行设计，拒绝旧报告和被篡改的证据。未出现某个能力或协同事实时保持未知，避免把“资料没写”误当成“不具备”。

## 优势发挥到什么程度

现在可以定位为：**本体已成为设计程序实际使用的语义知识层，基础的知识复用和推导解释已经体现；业务规则、计算与优化仍由专用引擎承担。**

比上一版仅有分类继承更进一步：能力和协同关系也进入业务流程。不过，旧Excel只填写角色和布尔标记时，仍主要使用传统显式输入；要体验新的关系知识复用，需填写本体类型、可选关系表及读取推导字段的规则。不能把所有历史案例都说成已经由本体推导完成。

## 尚未覆盖的工作

- 完整OWL推导结果回流、等价类、复杂匿名类限制、属性链、SWRL等没有实现。当前限定的推导规则集合不需要覆盖全部OWL语言。
- HermiT仍是独立的一致性检查入口，设计网页不会自动执行它。有限推导完成不代表已通过全套OWL一致性检查。
- 任务→能力的原文规则尚未全部落实；该层继续采用显式业务规则，没有通过本次改动自动增加文章没有给出的规则。
- 原文参数矛盾、真实协同数据和多任务事实缺口仍需确认。文章表13评分复算与完整候选筛选、六任务网络复现仍分开验收。
- 环境知识尚未形成影响能力与方案的数值模型；动态仿真、Neo4j展示和大模型接口不在本次接入范围内。

下一优先事项是确认B-Eidolon#1的真实参数、规则和关系，逐步核对“任务→能力→候选法器→候选链→评分”，再扩展多任务网络。现阶段无需为了“突出本体”而把数值计算和最优搜索全部改写为OWL。
