## 主要代码与运行

主入口为 `maintenance_demo/collaboration/summarize_workflows.py`。在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m maintenance_demo.collaboration.summarize_workflows
```

程序重新读取原始维修事实，调用 `collaborate` 验证可行性，再从生成的参与记录计算统计，不直接信任以前导出的 JSON。默认输出 `maintenance_demo/collaboration/generated/maintenance_statistics.json`；可用 `--input`、`--output` 和 `--max-combinations` 更换输入、统计路径及组合上限。

输出必须使用 `.json` 扩展名且不得覆盖输入。已有输出仅允许覆盖名为 `maintenance_statistics.json` 的文件，避免误覆盖其他 JSON 配置。退出码 0 表示完成；1 表示请求不可行；2 表示输入、路径或搜索上限错误。失败时不写入新报告；此前已有报告会保留，应以本次退出码判断成功与否。

## 指标定义

| 指标 | 计算口径 |
| --- | --- |
| 网络历时 elapsed_minutes | 最后一个任务结束减第一个任务开始；不计首任务之前的等待 |
| 任务工时 task_minutes | 各参与记录的持续时间之和；并行任务分别计入 |
| 活跃时长 occupied_minutes | 全部任务区间的并集长度，重叠部分只计一次 |
| 空闲时长 idle_minutes | 网络历时减活跃时长 |
| 峰值并发 peak_concurrent_tasks | 同时处于执行区间的任务数最大值 |
| 流程等待 idle_gap_minutes | 单条有序流程历时减其任务工时；包括任务之间的等待 |
| 资源占用时长 | 使用该资源的任务区间并集长度 |
| 资源工时 | 使用该资源的任务持续时间之和；多容量并发分别计入 |
| 资源容量利用率 capacity_utilization | 资源工时 /（整个网络历时 × 该资源容量） |
| 耗材计划余量 remaining_units | 输入库存减已验证计划的预留份数 |

资源表只列出实际被分配的资源。利用率的分母统一使用整个网络观察窗口，假定声明容量在窗口内保持恒定，不采用资源自身首末使用窗口。它是容量槽位利用率，不是“有任务时长 / 网络历时”。

区间沿用 `[start, end)`，前一任务结束与后一任务开始相同时不增加并发。所有时间单位为分钟，统计中的十进制数以字符串保存；容量、任务数和库存仍为整数。比例使用 Python Decimal 默认精度计算，循环小数可能舍入。

统计只读，不扣减实际库存，不改变任务、资源或已选分配。

## 与资料和后续工作的关系

这是维修计划的描述性统计，不是式（4）—（10）的领域评分实现。尤其不能将网络历时、任务工时和阶段耗时加法视为同一个量。

当前没有币种、费用率、耗材单价或实测维修质量，因此报告在 `unavailable_metrics` 中说明成本和质量缺少数据，不以零值代填，不从设备可用性推导精度，也不生成加权分数或方案排名。
