## 五、来源模块具体存什么

统一来源包至少有材料、表、字段定义、行记录、疑点和缺口六类对象，并带格式版本。

| 对象 | 要保存的字段 |
| --- | --- |
| 材料 | 稳定材料 ID、文件名、章节／表号／截图定位、转录文件摘要、核对日期 |
| 表 | 表 ID、所属材料、已知表名、输入中的 JSON 路径 |
| 字段定义 | 字段 ID、所属表、原键、已知原表头、类型说明、单位及其确认状态、单值或多值 |
| 行记录 | 记录 ID、所属表、行号或原行标识、准确输入路径、原对象代号（若有） |
| 字段值 | 所属记录、字段 ID、原始值、原类型、缺失状态、已有规范化值及依据、关联疑点 ID |
| 疑点／缺口 | ID、类别、说明、涉及记录和字段、出处、处理状态及已有依据 |

原始材料 ID、来源行 ID 和业务对象 IRI 是三种不同身份，不能互换。相同对象在多张表出现时先保留不同来源记录，不自动合并为业务对象。

来源层的单位是原表说明；缺失、未知、不适用、无量纲分开记录。核对日期不作为观测日期。JSON 已丢失的千位空格或原始数字字面写法不能由解析后的数值反造，原文件字节用摘要追溯。

本期以保留原值和已有解释为主，不新增有争议的数值转换。类型或单位解释待确认时，规范化值保持空；原表忠实转录通过，不等于疑点解决。

## 六、哪些字段怎样对应

### 6.1 来源 JSON → 通用来源结构

| 现有字段 | 对应内容 |
| --- | --- |
| `checked_on` | 人工核对日期 |
| `scope`、`source_alignment_policy` | 范围和处理原则 |
| `source_files` | 材料目录、来源定位 |
| `units` | 原单位说明与待确认状态 |
| `table7`、`table8` 等 | 来源表、行和字段原值；不根据表号生成业务类型 |
| `identity_mapping` | 名称对应的来源声明，不自动转成同一对象关系 |
| `explicit_facts` | 来源事实陈述及出处，作为归档记录 |
| `issues` | 独立疑点对象，关联原 code、记录和字段路径 |
| `missing_facts` | 缺口对象，不补默认事实 |

配置必须明确数组表和单对象表怎样读取。输入路径错误、重复标识、疑点指向不存在的字段要报错，不能静默跳过。

### 6.2 来源包 → 来源 RDF

拟使用独立命名空间 `urn:source-data:`，定义 Material、Table、Field、Record、FieldValue、Issue 和 Gap 等通用类，另设 SourceStatement 保存来源陈述。

每个对象用来源 ID 生成稳定 IRI。表引用材料，行引用表，值引用行和字段，疑点引用对应记录及字段。字段原值保存为带原类型说明的 JSON 文本或对应普通字面量，保留可还原性，不据字段名增加领域属性。

原始出处、疑点和归档值由这个来源本体承载，不放进环境的 `env:value`。导出后应能查回原记录、原值和原出处，且与来源包逐项一致。

### 6.3 适用的区域／环境数据 → 现有环境本体

这些是环境数据的输入契约，不从装备或任务表中猜测环境量：

当前区域已经在 `data/article_environment/environment.ttl` 中表达，可直接交给已有加载器复用，不需要先转成 JSON 再转回 TTL。`raw_tables.json` 不是环境观测输入文件。将来需要适配 JSON 等外部环境输入时，应先在 `adapters/README.md` 和 `adapter_mappings/environment.json` 中固定输入结构、必填字段、类型及标识对应；本节的字段表尚不能替代完整的机器可读输入契约。

| 已有明确输入 | 目标结构 |
| --- | --- |
| 区域稳定标识、名称 | `env:Area`、`env:name` |
| 参数标识、名称、含义 | `env:Parameter`、`env:name`、`env:definition` |
| 参数值类型、明确单位 | `env:valueDatatype`、`env:unit` |
| 参数定义出处及定位 | `env:source`、`env:sourceLocation` |
| 观测标识、参数引用、值 | `env:Observation`、`env:parameter`、`env:value` |
| 带时区的观测时间、明确区域引用 | `env:observedAt`、`env:area` |
| 观测出处及定位 | `env:source`、`env:sourceLocation` |

区域的出处通过通用来源引用或 rdfs:seeAlso 保存，不将 env:source 错加在 Area 上；当前环境校验只允许它用于参数和观测。

已经提供但缺必要字段的参数或观测必须报告不完整，不能静默降格成一条成功记录。只有实际未提供观测时，才走已有背景模式。有阻塞疑点的环境值保留在来源层，不导出为已经确认的观测。

## 七、加载以后实际能做什么

### 独立来源查询

新增来源入口加载通用来源本体和 provenance.ttl，提供以下查询：某份材料有哪些表和记录；某条记录有哪些原值、出处及疑点；哪些字段未确认；规范化值引用了什么依据。此入口不加载主本体或现有环境程序。

由拟新增的 `source_data/load.py` 负责上述 RDF 加载，`source_data/query.py` 负责查询，`source_data/cli.py` 统一暴露命令。实施阶段 1 必须先固定这三个文件的函数签名、返回结构和错误约定，再实现阶段 3；这些接口目前尚未存在，不能按现有环境接口推定。

### 独立环境查询

环境适配输出交给已有 environment.loader。参数目录可单独校验；实际观测可以按参数、区域和观测时间查询。只有区域时采用允许区域输入的校验接口，不能用“参数目录必须非空”的命令误判它失败。

### 当前项目背景查询

复用已有任务和态势背景文件，使用 integration.load_project 加载背景及区域／环境输出。默认无观测时返回 background_only；确有完整观测及用户提供的显式 hasObservation 关联时返回 observation_linked。

仅将 Area 加载到同一个图，不代表已经建立任务与区域之间的关系。当前背景查询证明的是任务→态势关联；无观测时不能据此宣称查到了任务对应的区域，按区域过滤也不会返回这条 background_only 记录。

来源 TTL 和来源本体可作为附加本地文件读入同一个图，但不得因此声称原有联合查询已经能输出所有来源元数据；追溯查询由新增来源入口负责。来源引用是追溯信息，不自动改变已有环境查询结果结构。

本期不自动创建任务、能力、装备、目标或通信／指挥关系。新增加的来源记录与已有背景对象若需追溯关联，只接受显式标识对应；不按名称、区域或时间自动建立业务关系。

## 八、实施顺序与每步验收

| 阶段 | 实施内容 | 必须拿出的验收结果 |
| --- | --- | --- |
| 1 | 固定来源包、来源本体和映射格式 | 每个字段归属明确；未决值政策明确；新命名空间不复制主本体类 |
| 2 | 只读导入来源 JSON、保留疑点 | 来源记录数量、原值、单位说明及疑点与输入一致；不改变输入文件摘要 |
| 3 | 导出来源 TTL 并独立查询 | JSON与RDF之间可追溯；查得到原值、出处、字段和疑点；无领域依赖 |
| 4 | 实现区域／环境适配 | 区域可独立导出；真实环境输入按既有模式校验；不完整记录有明确错误 |
| 5 | 接入已有背景入口 | 当前材料返回真实的 background_only 状态；不虚报观测数量 |
| 6 | 验证异常、文档与可重复运行 | 重复导入不随机换 ID；错误引用、类型及路径报错；输入不被覆盖 |

本批现有材料优先完成来源归档、疑点追溯和区域／背景接入。未有实际环境观测时，观测适配的结构和异常处理可作技术验证，但不得写成“真实观测案例已验收”。无需先补造环境数据才能交付其他阶段。

## 九、错误、状态及输出政策

结构错误、来源疑点、资料缺口、未提供独立环境观测分别统计。已确认原文如此与疑点已解决分开表示。

正常场景背景允许无观测；有格式错误或悬空引用的已有数据不能因此放过。严格观测验收继续采用已有 `--require-observations`，不修改其含义。

新命令标准输出为 JSON，诊断写标准错误。退出码建议沿用 0 成功、1 校验失败、2 输入／命令错误；输出必须同时带状态和计数。退出码 0 不表示原文无疑点。

输出不得覆盖来源、配置或模块文件。已有输出默认不覆盖，显式覆盖也须先验证并以临时文件原子替换，避免失败时破坏上一版有效结果。映射配置禁止脚本表达式、eval 和外部命令。

## 十、最终完成标准

完成时必须同时交付代码、配置、可运行说明和分类验收报告。验收至少证明：

1. 独立来源模块能导入、验证、导出 RDF 并查回原值、来源和疑点。
2. 当前来源文件的原值及已有身份对应不被修改，未决内容不静默变成规范化值。
3. 区域及有依据的环境数据可以生成既有加载器接受的 TTL，来源可以追溯。
4. 当前截图背景材料通过背景模式，明确无独立观测；严格模式仍如实提示缺失。
5. 不要求用户再次整理已经给出的疑点，不把未提供的材料编成事实。
6. 报告清楚写明：完成的是来源管理与区域／环境数据接入，未完成完整业务案例和自动设计流程。

本期到此结束，不再把装备／目标的业务映射、攻击链推理或评分作为本计划后续默认阶段。
