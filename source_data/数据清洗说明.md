# 独立数据清洗与检查

在项目根目录执行，无需启动网页，也不生成本体实例：

```powershell
.\.venv\Scripts\python.exe -B -m source_data.cli clean data/article_source/case_records.json --output-dir generated/case_cleaning
```

此入口接受项目规定格式的案例JSON，Excel输入仍使用提供的模板。输出目录已有文件时默认拒绝覆盖；可换新目录，或明确增加 `--overwrite`。原始输入始终不修改。

输出内容：

- `cleaned_case.json`：清理文本首尾空白、去除列表重复项后的派生数据。数值保持输入声明的单位，不自动修复上下界或交换坐标。
- `cleaning_report.json`：校验状态、输入内容摘要、每处文本/列表变更、自动发现的问题，以及 `normalized_numbers` 单位换算明细。换算明细记录字段路径、原值、输入单位、输出单位、换算因子和十进制结果字符串，避免JSON浮点舍入。

独立清洗与本体映射使用同一换算函数，支持的单位与共享案例契约一致。报告保留坐标列名冲突、上下界倒置等待核对事项；结构检查通过不代表这些事项已解决，也不证明来源事实真实。来源JSON和原始Excel另行保留，不将清洗副本当作原始资料。

## 案例导入与校验

使用当前四表映射时，`source_data.cli ingest` 自动执行案例字段检查，并在来源包之外生成上述两个清洗文件。网页使用该入口，所以网页与命令行得到同样的清洗输出。Python `ingest()` 也执行同一案例契约。

`source_data.cli validate` 和 `export` 自动识别四表案例映射，并增加案例字段检查。概率超过范围、非法坐标、负数、缺失字段、编号冲突或悬空平台引用不会被当作合格案例通过。

报告中的 `validation_scope` 明确区分：

| 项目 | 含义 |
| --- | --- |
| `source_integrity` | 来源包与保存的原始快照、映射及所指定原文件是否一致 |
| `case_contract` | 是否执行并通过案例字段契约检查；未执行显示 `not_run` |
| `external_source_truth` | 始终为 `not_verified`，程序不判断文章或图片中的事实真伪 |

通用来源层的 `build_bundle()`、RDF原值读取和默认 `validate_bundle()` 仍允许归档有问题的原始资料。它们的作用是如实保存来源，而不是把输入判为合格案例；报告明确标注案例检查未执行。需要通过Python单独检查案例包时使用 `validate_bundle(bundle, check_case=True)`。其他表结构的通用映射不会被误当作当前四表案例。

任务目标、能力关系和未确认字段的语义映射仍需另行核实。本步骤不推断或补造这些信息。
