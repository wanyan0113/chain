# 案例数据到本体实例

Excel 网页导入现在依次执行来源整理、来源校验、RDF 查询、本体实例映射和静态检查。当前映射只描述资料中的对象及关系，不运行设计规则。

## 网页使用

在项目根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\启动Excel演示.ps1`，打开 `http://127.0.0.1:8765`，导入案例示例。运行结果中显示实例映射状态，选择记录后可看到对应实例类型、承载关系及来源记录标识。

输出保存在页面显示的本次结果目录的 `results` 子目录中：

| 文件 | 内容 |
| --- | --- |
| instances.ttl | 实例、属性、来源记录及字段级追溯信息 |
| ontology_with_instances.ttl | 主本体、来源本体及本次实例的合并文件，可直接在 Protégé 打开 |
| instance_report.json | 实例清单、字段映射、未映射字段、来源疑点数量及检查结果 |
| instance_summary.md | 便于阅读的字段覆盖、清洗及待确认事项摘要 |

在 Protégé 中打开 `ontology_with_instances.ttl` 后，在 Individuals 中选择具体实例，查看类型、属性及 `hosts` 承载关系。`prov:wasDerivedFrom` 关联来源记录；每项已映射属性还有 `rdf:Statement` 形式的字段级来源。来源记录继续通过来源包中的关系关联表和资料材料。

## 映射范围

- 对象清单：保存为 `urn:case-instance-mapping:ObjectCollection` 集合描述及列示数量，不将一行数量展开成多个虚构个体。集合不是装备实例，与同名具体平台使用不同标识。
- 探测能力表：平台映射为 `ArtifactPlatform`，资源映射为 `InsightArtifact`，用 `hosts` 关联。映射已明确单位的高度、距离及类别文本。
- 作用能力表：资源映射为 `ManifestationArtifact`，关联已在探测能力表登记的平台，映射明确单位的距离、高度和速度等原始属性。
- 任务表：映射为 `ArcaneMission`，保存任务名称、类型文本及有明确单位的高度、速度。不从任务名称拆出目标编号。任务到具体目标和所需能力的关系使用附有来源的显式配置。

当前示例生成32个实例条目，包括7个集合描述、4个平台、10个资源、10个资源基础能力和1个任务。基础能力只表示所属功能类别，不表示已通过适用性推理。集合描述与具体个体不能混为一谈。

139个来源字段值分为22个编号用途、96个属性或关系用途和21个仅保留原值，三类互不重叠。编号同时用于属性时仍只在编号类计数，不重复统计。仅保留原值的字段包括坐标、精度、作用值和目标阈值，报告逐项给出原因。映射状态 `valid` 与覆盖状态 `pending_confirmation` 分开显示，不代表全部字段都已解释。

概率字段已映射：声明单位为 `%` 时95转成0.95，声明为 `1` 时直接使用0—1值，并保留转换依据。网页与独立映射入口共用 `source_data/case_contract.py` 的类型、范围、必填、编号和平台引用检查；独立入口同样拒绝概率200、负数及缺失值。

派生视图支持文本首尾空白清理、列表去重，以及声明单位的转换。距离支持 `n mile`、`nmi`、`km`、`m`，高度支持 `ft`、`m`，速度支持 `kn`、`kt`、`km/h`、`m/s`，概率支持 `%`、`1`。本体输出统一为n mile、ft、kn和0—1。转换使用十进制运算，乘法精度随输入及因子位数增加，同单位转换不会舍入超长整数；循环小数换算因子仍为有限精度近似值。原始输入、来源包和来源查询不改写；转换因子记录在属性追溯中。

坐标接受十进制度或度分秒，检查度数范围、分秒小于60及极值边界；非法文本直接拒绝。带方向坐标按方向检查范围，列名与方向冲突另行提示，不自动交换列，也不据此完成尚待核实的坐标映射。

程序自动标记距离或高度上下界倒置、坐标方向与列名不符；保留原值，不交换字段或猜测缺失值。自动检查结果与人工登记疑点分别记录，不重复计算成“已修复”。

坐标、精度、未确认量纲的值和正文关系继续保留在来源层，报告明确列出未映射字段。不会自动将原始精度90转换为0.9，也不自动交换坐标或修正距离上下界。来源中的疑点和缺口继续保留；`valid` 仅说明本次映射和结构检查通过，不表示业务矛盾已经解决。

检查包括来源包一致性、必要字段、数值类型、单位、重复资源编号、平台引用及本体静态结构。平台引用必须在探测能力表登记，不从编号前缀猜测其存在。`启动Excel演示.ps1` 默认启用HermiT完整OWL一致性检查；依赖缺失或检查失败会终止本次导入。直接运行Python入口仍需指定 `--reasoner`，未启用时报告明确记录 `not_run`。

## 独立运行

已有来源包时，可在项目根目录执行（将路径换成本次文件的实际位置）：

```powershell
.\.venv\Scripts\python.exe -B -m adapters.case_instances generated/article_source/bundle.json --output-dir generated/case_instances
```

已有输出默认拒绝覆盖。实例标识包含来源包摘要，因此输入修改后会得到新的实例快照，不能将两次快照当成同一批数据直接合并。

## 完整OWL检查

需要本机Java，以及一次性安装可选依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-reasoner.txt
.\.venv\Scripts\python.exe -B -m excel_entry.app --reasoner
```

独立映射命令也可增加 `--reasoner`；或对已有文件单独检查：

```powershell
.\.venv\Scripts\python.exe -B -m adapters.owl_check generated/case_instances/ontology_with_instances.ttl
```

HermiT在独立子进程执行，超时、依赖缺失和未执行不会标成通过。只检查本地合并图，不自动联网加载 `owl:imports`。一致性通过不证明原始资料真实或业务规则正确。

## 显式任务关系

`source_mappings/case_instance_links.json` 默认是空配置，不自动认定任务目标。配置结构如下，示意编号需替换为实际核实值，不能将此示意当成案例事实：

```json
{
  "format_version": 1,
  "tasks": [{
    "record_path": "table11",
    "target": {"id": "已核实的目标编号", "source_keys": ["table11"]},
    "capabilities": [{"id": "已核实的能力编号", "type": "InsightCapability", "source_keys": ["case_text"]}]
  }]
}
```

能力类型允许 `InsightCapability`、`CoordinationCapability`、`ManifestationCapability`。`source_keys` 必须引用当前来源包已登记的材料键；程序检查引用存在，不替代人工核实材料是否支持该关系。目标可用 `null`，能力可用空数组表示尚未确认。未配置的任务关系始终显示待确认。

使用 `--bindings source_mappings/case_instance_links.json` 将配置交给网页入口或独立映射入口；配置及来源保存在输出报告中，配置变化会改变实例快照标识。
