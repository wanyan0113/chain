# 案例数据到本体实例

Excel 网页导入现在依次执行来源整理、来源校验、RDF 查询、本体实例映射和静态检查。当前映射只描述资料中的对象及关系，不运行设计规则。

## 网页使用

在项目根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\启动Excel演示.ps1`，打开 `http://127.0.0.1:8765`，导入案例示例。运行结果中显示实例映射状态，选择记录后可看到对应实例类型、承载关系及来源记录标识。

输出保存在页面显示的本次结果目录的 `results` 子目录中：

| 文件 | 内容 |
| --- | --- |
| instances.ttl | 实例、属性、来源记录及字段级追溯信息 |
| ontology_with_instances.ttl | 主本体、来源本体及本次实例的合并文件，可直接在 Protégé 打开 |
| instance_report.json | 实例清单、字段映射、未映射字段、来源疑点数量及检查结果 |

在 Protégé 中打开 `ontology_with_instances.ttl` 后，在 Individuals 中选择具体实例，查看类型、属性及 `hosts` 承载关系。`prov:wasDerivedFrom` 关联来源记录；每项已映射属性还有 `rdf:Statement` 形式的字段级来源。来源记录继续通过来源包中的关系关联表和资料材料。

## 映射范围

- 对象清单：保存为 `urn:case-instance-mapping:ObjectCollection` 集合描述及列示数量，不将一行数量展开成多个虚构个体。集合不是装备实例，与同名具体平台使用不同标识。
- 探测能力表：平台映射为 `ArtifactPlatform`，资源映射为 `InsightArtifact`，用 `hosts` 关联。映射已明确单位的高度、距离及类别文本。
- 作用能力表：资源映射为 `ManifestationArtifact`，关联已在探测能力表登记的平台，映射明确单位的距离、高度和速度等原始属性。
- 任务表：映射为 `ArcaneMission`，保存任务名称、类型文本及有明确单位的高度、速度。不从任务名称拆出目标编号，不补造目标或能力实例。

当前示例生成22个实例条目，包括7个集合描述、4个平台、10个资源和1个任务。集合描述与具体个体不能混为一谈。

坐标、精度、未确认量纲的值和正文关系继续保留在来源层，报告明确列出未映射字段。不会自动将原始精度90转换为0.9，也不自动交换坐标或修正距离上下界。来源中的疑点和缺口继续保留；`valid` 仅说明本次映射和结构检查通过，不表示业务矛盾已经解决。

检查包括来源包一致性、必要字段、数值类型、单位、重复资源编号、平台引用及本体静态结构。平台引用必须在探测能力表登记，不从编号前缀猜测其存在。不调用完整 OWL 推理机。

## 独立运行

已有来源包时，可在项目根目录执行（将路径换成本次文件的实际位置）：

```powershell
.\.venv\Scripts\python.exe -B -m adapters.case_instances generated/article_source/bundle.json --output-dir generated/case_instances
```

已有输出默认拒绝覆盖。实例标识包含来源包摘要，因此输入修改后会得到新的实例快照，不能将两次快照当成同一批数据直接合并。
