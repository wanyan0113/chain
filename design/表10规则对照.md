## 已补充：给定并行链组的协同核验

```powershell
.\.venv\Scripts\python.exe -B -m design.article_cooperation design/examples/table10_parallel_demo.json
.\.venv\Scripts\python.exe -B -m unittest tests.test_article_cooperation -v
```

这是独立核验入口，输入中必须明确声明 `mode=declared_parallel_group`，所有输入链被视为同一并行组。每个任务只能提供一条待核验链；重复身份、悬空引用、角色不符和无效数据会报错，不能把多个候选当作同时选中链。

| 原文条件 | 本次实际检查 |
| --- | --- |
| 法器有传讯关系，距离小于最大传讯距离 | 对每条链探知→协调、协调→具现两段分别检查，有向边不自动补反向，距离相等不通过 |
| 统筹与具现之间有统筹关系 | 协调→具现边需显式controls=true；缺失为unknown，false为fail |
| 探知、统筹法器可在多条链中 | 允许共享，再逐项核验对应范围和目标数量条件；不把“可共享”当作无限容量 |
| 具现法器只能在一条链中 | 给定组内重复引用同一具现法器即fail，不从库存数推断可重复使用 |
| 共享探知距离同时大于所有任务目标距离 | 对使用该探知法器的每个任务分别比较，不用单个任务距离代替其他任务 |
| 共享探知最大标记数大于目标总数 | 对共享同一探知法器的任务目标数量求和，严格大于；不是链数，也不是大于等于 |
| 共享统筹最大解析数大于目标总数 | 对共享同一协调法器的任务目标数量求和，严格大于 |

单个法器未被多链共享时不触发共享数量规则，仍需由筛选入口检查单任务适配。缺失数量、距离或通信事实均报告unknown；已确定失败与未知可以同时保留，汇总为fail表示该组已明确不满足至少一项，而非其他事实都已确认。提供全局blocking_issue_ids可阻止含未决问题的输入汇总为pass。

报告保存输入快照、来源、逐项条件和数值依据。构造示例两个目标、最大标记数/解析数均为3，因此严格大于2；改为2即失败。每组共享资源分别求和，不把不同探知/协调法器的任务混算。示例不是文章案例，未按它补入原文缺失事实。

该入口尚未接入完整设计引擎的候选搜索、Excel或网页，也不自动从时间区间划分并行组、不验证串行重用和动态仿真。完整设计原有容量/库存政策继续保留，不把两套约束宣称为相同。判定pass只说明给定并行组的这些表10条件通过，不表示能力、法器筛选、可用性、评分或完整网络已验收。
