## 实际检查

`scene.ttl`：1 个任务引用、1 个场景态势；`environment.ttl`：1 个区域、0 个参数、0 个观测；`links.ttl`：0 条态势—观测边。

从仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -m integration.load_project --project data/article_environment/scene.ttl --environment data/article_environment/environment.ttl --links data/article_environment/links.ttl
```

默认场景背景模式下，本批输入预期退出码为 0，返回 1 条 `background_only` 记录。报告会提示未关联观测，不能据此声称完整环境观测接入或环境作用已验证。实际检查详情见 `check_report.json`。

本轮实测：合并后的 RDF/OWL 静态检查为 0 错误、0 警告；默认背景模式 0 错误、2 个观测缺失警告，返回 1 条任务—态势关联，退出码为 0。

在命令后追加 `--require-observations` 时，严格模式报告 `NO_TARGET`、`NO_CONNECTION`、`LINK_GAP`、`NO_PATH` 四项错误，退出码为 1。四项错误来源于同一条观测路径的缺失，不是四个独立的代码故障，也不是文章必须补齐的四种属性。

此前把严格观测模式作为唯一验收标准，导致本场景整体失败，已纠正。不要为了通过严格模式而填写当前日期、假定环境值或把表 8/11 的位置和速度改成环境参数。

## 还需要什么

如果研究目标仍是检验环境接入，需要从原始材料或平台取得至少一项环境参数的定义、单位（适用时）、实际值、带时区观测时间及区域，并提供出处和它与本场景的显式关联。图片中的“某日”不能转换为确定时间。

如果原文案例本身没有这些数据，应记录“场景背景接入通过，未提供独立环境观测”，不能声称已完成环境作用验证，也不阻塞场景背景接入。无需你先制造一份环境数据才能做出这个检查结论。
